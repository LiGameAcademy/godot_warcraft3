# Echo Isles 1v1 开发规范

适用首版 GDScript 对局、表现及 LAN 装配。模块边界见 [对局架构](../design/game/ARCHITECTURE.md)，联机消息见 [LAN 契约](LAN_MATCH.md)，既有运行态见 [状态所有者](STATE_OWNERS.md)。

## 源码与场景

- 对局装配放在 `apps/game/app/`，输入与表现放在 `apps/game/client/`，跨应用共享规则在 `packages/` 源头维护。使用工作区同步生成应用依赖。已确认的 GDScript 路径承担首版玩法，C# RTS 内核接管延期。
- GDScript 的成员、局部变量、参数、返回值与信号载荷显式标注类型。已知元素的集合标注元素类型。网络、导入和旧动态配置在边界校验并转换后交给规则。
- 文件、目录、变量和方法用 snake_case，类、节点与 Autoload 用 PascalCase，常量与枚举成员用 UPPER_SNAKE_CASE。路径大小写与实际资源一致。自维护代码每个文件最多 500 物理行，修改前后检查；触及超限文件时按真实职责拆分并验证行为。
- 稳定节点树放在场景中。新增可复用游戏对象用独立场景和同名入口脚本。纯计算和 Resource 直接复用。通过显式参数、`@export` 和 `@onready` 表达依赖。父调用子公开方法，子发信号，兄弟由共同父级协调。
- 现有对象定义、费用和时长保持单一数据来源。静态配置只读，生命、计数、临时数据及运行时改写的资源按实例独占。修改嵌套可变 Resource 时验证复制隔离。

## 意图、写入与清理

| 边界 | 实现要求 |
| --- | --- |
| 输入 | HUD、鼠标、本地 AI 和远端都提交意图，经现有命令与规则入口。预览可以预测是否合法，正式写入由权威侧再次验证。 |
| 提交 | 在扣费、排队、落地前校验权限、阶段、目标与前提。失败保持库存、人口、队列与占位一致。取消和销毁按领域所有者释放状态，避免退款或死亡结算重复执行。 |
| 权威 | 本地 PvE 由本地会话推进，LAN 由房主推进。客机只提交命令并消费状态。各领域维持一个写入口，表现读取结果或事件。 |
| 局生命周期 | 结算只锁存一次。结算后拒绝新局内命令并停止模拟。卸载解除信号、回调和连接，重开用新局号。验证旧回调与旧网络消息无法修改新局。 |
| 诊断 | 关键拒绝与状态变化记录局号、玩家或 peer、命令序号、实体及原因。保留足够上下文复现。游戏启动标记、专项断言和引擎错误分别检查。 |

## 开发自检

每次改动由开发对话在交接前完成自检。按下表选择受影响项，用正常入口跑通一条代表路径。涉及规则、权限或清理时，再跑一条相关拒绝或失败路径，检查状态是否符合预期。纯文档改动检查链接、路径和描述的一致性。记录实际运行的命令或操作、结果及未覆盖项。影响开局、联机同步、胜负或重开时，交接候选前再跑一遍受影响的完整流程。

| 改动 | 最低验证 |
| --- | --- |
| 脚本、场景或资源 | 同步、导入、脚本解析、实例化及正常 Boot。改动信号时验证方向与卸载。改动可变资源时验证 A/B 隔离。 |
| 核心规则 | 无 HUD 夹具验证成功和拒绝路径，再用真实地图确认普通输入能走到相同入口。训练、取消、死亡与重开记录前后状态。 |
| 联机 | 验证内容不匹配、越权、重复、乱序、掉线与旧局消息。实体双机单列，核对同一候选、同局号、双方视角及房主日志。 |
| 表现 | 规则状态与视觉反馈一致，镜头和画质变化不改变结算。按 [美学规范](../design/presentation/EI_VISUAL_STANDARD.md) 留截图或录像。 |

运行入口见 [自动测试索引](../tests/README.md) 和 [项目复测](../test-cases/MELEE_ACCEPTANCE.md)。新方案在设计中标明待实现或待验收，随实际接入更新状态。

## 候选交接

开发对话交付固定候选，并在对应 Issue 附上以下证据。

- 候选 ID、游戏提交及工作区状态、依赖与 Godot 版本、Windows 包位置和 SHA-256 清单，以及地图与资产版本。联机两端核对同一份清单。
- 改动范围、受影响的需求和验收用例、正常启动与复现步骤。联机写明房主与客机操作、连接方式和日志入口。
- 自检用例的预期和实际结果、执行环境、命令与退出码（如适用）、原始日志，以及用于判断结果的截图或录像。联机证据标注双方身份和同一对局 ID。
- 已知限制、未执行项、失败项及复现条件。阻断本轮验收的缺口标明待修或待补证据。候选有变化时重新标识，并列出受影响的复验项。

## 独立验收与关闭

设计对话定义可观察的通过条件。开发对话交付候选和自检证据。验收对话使用同一固定 Windows 候选独立执行课程总仓库 `docs/verification/echo_isles/EI_1V1_ACCEPTANCE.md` 的 EI-A01 至 EI-A08，保留自己的操作记录和原始证据。

关闭里程碑前，独立验收须确认干净启动和真实地图开局、正常资源下完成单机 PvE 一胜一负、两台 Windows 机器完成 LAN PvP 一整局且双方状态与胜负一致、房主拒绝越权命令、断线后可以退出和重新组局，以及两种模式按剧本交换出生位并重开且无旧局状态残留。正常对局使用常规操作完成。验收逐项记录通过、失败、阻塞或未执行。必验项全部通过且证据齐全后，管理对话据此关闭里程碑。
