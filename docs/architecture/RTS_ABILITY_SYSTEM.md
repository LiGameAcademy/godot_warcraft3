# RTS Ability System — 精简 C# 技能模块

日期：2026-09-27。状态：设计基线，接口名和 JSON 示例为拟定契约，尚无加载器实现。

关联：[内核设计](RTS_KERNEL.md) · [迁移验收](RTS_KERNEL_MIGRATION.md)。

## 1. 目标与范围

为当前已实现技能提供易上手且可扩展的纯 C# 模块。保留过去 AbilitySystem 的技能、效果、状态、属性修正等概念与教程关联，不逐类翻译整个插件，不要求 GDScript 双版本维护或旧资源/API 兼容。

采用三层扩展：模板处理常见执行流程；数据组合已有效果；特殊机制注册专用 C# 行为。不要求行为树编辑体验，不移植通用行为树/动态黑板/观察者框架，不开发新可视化编辑器或脚本虚拟机。

## 2. 定义、运行态与执行行为

### 冻结定义

AbilityDefinition 包括稳定 ID、目标过滤、距离、费用、冷却、时序、模板/行为 ID 与效果参数。BuffDefinition 包含时长、叠加/刷新规则、周期效果、属性修正与已支持的免疫/驱散语义。

定义在对局开始前完成校验并冻结；独立于 Godot Resource。逻辑定义与表现映射分开，内核输出 cue/ability ID，Godot 将其映射为模型、动画、音效和预览。

### 可保存运行态

AbilityState 记录等级、禁用/开关状态、冷却截止帧与自动施法开关；CastState 记录施法实例 ID、阶段、目标、位置、开始/截止帧、费用是否已提交、剩余波次及行为专属数据。

BuffInstance 记录实例 ID、定义、来源、目标、层数、结束帧、下次周期帧等。具体字段按实际机制添加，不能把任意对象字典当作稳定存档契约。

行为实现由固定注册表查找；快照保存行为 ID 与显式状态，不保存函数指针、Task、协程或闭包。注册表启动后冻结，运行中不可更换语义。

### 基础结算共享

生命/法力、伤害、治疗、Buff、属性修正与目标过滤提供统一机制。普通攻击保留攻击状态机；物品保留库存和次数管理；它们调用共享效果服务，不强行转换成技能。

Buff 对属性的修改使用明确的修正项身份和稳定计算顺序，不能靠结束时减回旧值恢复。形态变化、基础属性变化与 Buff 共同作用须可重算并通过测试。

## 3. 三层扩展方式

### 模板

候选模板：瞬发、目标弹道、引导、开关、被动触发、光环。只实现当前技能需要的部分，不预先堆积配置开关。

通用流程：请求校验 → 按现有规则接近 → 前摇 → 提交费用与冷却 → 执行 → 完成/中断。不同模板可以有明确的提交时机，不能让效果各自重复扣费。

自动施法属于命令生成策略，使用同一合法性与费用入口。被动和光环是确定性系统状态，不依赖表现节点事件。

### 效果组合

支持按顺序执行伤害、治疗、施加/移除状态、召唤、位移等已需要的效果。定义明确的执行时点，例如 onCommit、onImpact、onPulse。先不提供任意循环/条件表达式语言。

效果返回 Applied、NoEffect、Rejected 等可诊断结果。失败后是否继续执行后续效果由阶段/组合规则明确定义；默认保持已提交效果，不隐式回滚已经发生的伤害。费用提交事务与效果执行链分开：不能一遇到目标死亡就自动退款。

例如伤害致死后对同一目标施加眩晕，应通过目标有效性检查得到 NoEffect；目标死亡不等于之前的伤害失败。具体语义以既有技能逐项冻结。

### 自定义 C# 行为

通过行为 ID 注册，使用窄的内核查询与结算接口。初始候选回调为开始、逐帧推进、取消；方法名可调整，但调用时机、状态所有者和结果必须固定。

可复用现有模板，也可提供专用阶段状态；不得绕过命令合法性、费用、随机流或快照契约。行为代码不读取文件、场景、网络或现实时间。

例：多波暴风雪保存区域、剩余波数与下一波帧；连锁机制若未来实现，保存已命中 ID、剩余跳数和下一跳帧。后者仅为扩展说明，不新增本轮功能范围。

## 4. 内容来源与 JSON

现有 SLK/表格加载流程保留，经旧内容转换器产生统一定义。新增 JSON 文件同样产生该定义。每个技能 ID 只有一个来源；相同 ID 即使内容相同也报错，禁止隐式覆盖、继承或字段合并。

JSON 加载、Schema 与语义校验属于外层内容模块。内核只接收冻结定义，不关心 CSV/SLK/JSON 或文件路径。只支持 JSON，不同时实现 YAML。

归一化后的有效模拟内容用于内容哈希：对象字段稳定排序、默认值显式展开、单位统一、效果数组顺序保留、有限数值规范编码。空格和对象字段排列不影响哈希；效果顺序改变必须影响哈希。表现资源不参与模拟哈希，另行管理其版本。

对局中不可热更新。修改数据需重新创建对局；旧快照遇到不同有效内容版本拒绝恢复。

## 5. JSON 示例与验证契约

以下是用于讲解结构的新增示例技能，不是现有 WC3 技能的权威数值，也不覆盖已有 ID。单位为 WC3 距离单位和秒，加载阶段按统一规则换算逻辑帧。假设演示状态 demo.stun 已定义。

```json
{
  "schemaVersion": 1,
  "id": "demo.storm_bolt",
  "template": "target_projectile",
  "target": {
    "kind": "unit",
    "relation": "enemy",
    "requireAlive": true
  },
  "cast": {
    "range": 600.0,
    "windupSeconds": 0.3,
    "manaCost": 75.0,
    "cooldownSeconds": 9.0,
    "commitAt": "launch"
  },
  "projectile": {
    "speed": 1000.0,
    "homing": true
  },
  "onImpact": [
    { "type": "damage", "amount": 100.0, "damageKind": "spell" },
    { "type": "apply_buff", "buffId": "demo.stun", "durationSeconds": 2.0 }
  ]
}
```

发布的示例包必须同时提供引用的 Buff 和其他定义，不能只交付孤立 JSON。

Schema 检查类型、必填项、枚举、数值范围与未知字段；语义校验检查重复 ID、未知模板/行为/效果、缺失 Buff、相互冲突的时序选项和非法组合。NaN/Infinity 等非有限数值拒绝。加载失败阻止创建对局，错误包含文件、技能 ID 与字段路径。

Schema 与语义校验缺一不可。SDK 校验库及 Schema 方言在实现批次锁定；本设计不声称已有 Schema 文件或可运行示例。

技能多级数值按当前数据逐级归一化，不依赖运行时表达式求值；JSON 多级结构在迁移现有英雄技能时明确并提供完整示例，不能因为示例是单级就丢失等级能力。

## 6. 消耗、中断与快照规则

- 提交前统一检查费用与目标；提交点再次检查可能变化的条件。
- 成本、冷却及物品次数只提交一次；保存提交状态，恢复不重扣。
- 中断前摇、引导、死亡、目标失效、订单替换分别有显式处理；不能只提供一个含义模糊的 cancel。
- 引导周期统一按逻辑帧推进，明确首波触发时机与最后一波是否包含结束帧。
- 源单位死亡后弹道是否继续、Buff 是否保留、召唤是否消失，先按现有技能行为迁移，不擅自统一。
- Buff 同帧到期与技能结算遵守主文时序契约；恢复后不得重复注册可产生多次效果的订阅。
- 表现事件包含施法实例/效果实例与帧内序号；持续表现可从状态重建，一次性特效不参与模拟恢复。

## 7. 当前技能迁移与教学交付

以实际已实现能力为清单：治疗、风暴之锤、雷霆一击、暴风雪、水元素召唤、群体传送、减速、心灵之火、顶盾、天神下凡、重击、辉煌光环、自动施法及当前英雄/物品联动。实施时逐项确认源码行为和测试，不把列表视为所有 WC3 技能支持声明。

教程交付按三条路径：修改已有参数、组合已有效果、添加自定义行为。提供至少治疗、弹道眩晕、引导范围攻击与一个现有技能的专用行为示例。说明新旧 AbilitySystem 概念映射，不要求双版本 API 一致。

测试入口可创建施法者/目标、提交技能命令、推进指定帧数，检查阶段、费用、冷却、效果结果与取消。必须包含技能运行中快照恢复及重放一致性。

## 8. 实施时需要冻结的细节

模板精确字段、等级结构、各技能提交/中断规则、Buff 叠加及修正顺序，根据现有实现建立行为样本后冻结。先保证已有玩法，不以“简化系统”为由删除技能能力。

抽成独立通用插件、编辑器、配置继承、热重载、任意脚本与 GDScript 包装作为未来可选方向，均不作为本轮验收依赖。
