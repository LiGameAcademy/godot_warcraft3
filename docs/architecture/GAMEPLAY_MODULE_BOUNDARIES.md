# Gameplay 模块划分与接口责任

日期：2026-09-23。状态：目标设计，非实现完成清单。

衔接 [四方面分层与迁移策划](GAMEPLAY_REFACTOR_PLAN.md)；UI 详见 [布局重设计](../design/game/HUD_LAYOUT_REDESIGN.md)。

## 组织原则

按功能划分模块，功能内部区分输入、命令、状态、行动及表现。输入→命令→行动是处理链，状态是命令与行动使用的数据基础。模块不等于 Autoload，不强制每个模块对应一个管理器或独立包。小功能可先共同发布，但必须明确状态所有者和接口。

## 模块目录

| 模块 | 拥有的状态 / 核心职责 | 对外边界 |
|---|---|---|
| 对局与规则 | 玩家、队伍、对局阶段、时间、胜负 | 启停运行系统，不代执行单位行动 |
| 实体生命周期 | 实体身份、注册、出生、移除、能力装配 | 身份查询与生成/销毁；不集中持有所有组件数据 |
| 命令与订单 | 请求结果、单位订单、排队/替换/取消、中断仲裁 | 玩家、AI、触发器共用请求入口 |
| 导航与移动 | 路径、动态障碍、预约、局部避让、移动进度 | 接收目的地与约束，不决定战略目标 |
| 战斗 | 攻击时序、命中、伤害、投射物、死亡结算 | 统一伤害入口，不让技能/物品各自扣血 |
| 技能与效果 | 施法、目标规则、消耗、冷却、引导、效果组合 | 注册行为与施法请求；不依赖 HUD 选择 |
| 状态效果 | Buff/Debuff、叠加、时限、驱散、属性修正 | 被攻击、技能、物品复用；初期可随技能模块发布 |
| 经济 | 玩家库存、人口、支付、退款、变更记录 | 提供明确的支付/退款结果；不执行农民采集 |
| 采集 | 资源节点、携带、采集/运输/交付行动 | 通过经济接口入账，通过导航移动 |
| 建造 | 放置合法性、占地、工地、施工、取消/拆除 | 预览独立；通过经济支付，通过导航接口更新占地 |
| 生产与科技 | 训练/研究队列、科技条件、进度、升级 | 通过实体模块生成单位，向 UI 提供队列快照 |
| 物品与背包 | 地面物品、背包、装备、使用、掉落、商店交易 | 效果与技能共用机制，费用走经济接口 |
| 感知与迷雾 | 视野源、探索记录、当前可见、隐形侦测 | 向渲染、UI、目标查询及 AI 提供授权可见信息 |
| 群体移动与编队 | 成员、队形槽位、目的地分配、重组、到达协调 | 为导航提供不同目标，不重写寻路 |
| 单位 AI | 警戒、自动索敌、反击、追击范围、返回 | 产生低优先级意图，遵守命令控制权 |
| 对战 AI | 经济规划、扩张、生产、侦察、进攻、防守 | 使用正常命令入口，遵守经济/可见性规则 |
| 地图事件与触发器 | 事件订阅、条件、动作、定时任务 | 经版本化查询/命令端口影响世界 |

领域死亡由战斗/生命逻辑确认，实体模块负责移除身份，表现模块负责尸体动画；三者不可各自判定另一套死亡事实。位置与在场性也只保留单一权威，沿用 WorldMembership 的进矿/施工语义。

## 编队与 AI 的不同层级

| 概念 | 所属位置 |
|---|---|
| Ctrl+数字保存选择集合 | 本地交互的控制组，不是队形 |
| 多单位移动时分配落点 | 群体移动 |
| 横队、纵队、护卫、保持间距 | 编队规则 |
| 单位自动反击 | 单位 AI |
| 小队集结、撤退、集火、护送 | 对战 AI 内的战术协调；规模增长后可独立模块 |
| 扩张、科技、军队组成 | 对战 AI 战略规划 |

对战 AI：战略计划→经济/生产计划与战术任务→单位请求→订单→行动。单位 AI 只能在明确授权条件下提交自动行为；玩家移动、停止、坚守、施法等如何抑制/恢复自动行为，必须有统一规则。不可由多个控制器每帧竞相覆盖订单。

迷雾不只隐藏模型：目标查询、UI、AI 都必须经过感知边界。已探索但当前不可见的敌方建筑，可显示带时间语义的最后已知信息；不能继续更新其真实生命和生产状态。

## 非 Gameplay 核心模块

- 内容与资源加载：定义、资产、内容包、Mod、缓存，区别于经济资源。
- 本地玩家交互：选择、控制组、输入、相机、瞄准。
- UI：布局外壳、选择详情、命令面板、生产/研究、英雄、背包、通知、小地图、设置。
- 世界表现与音频：模型、动画、特效、音效，消费状态和事件。
- 存档恢复：稳定身份与数据版本；不直接将场景树作为长期存档协议。
- 诊断：性能、实体、订单、状态检查；不拥有玩法权威。
- 联网/回放：仅保留身份和命令扩展边界，未承诺多人确定性或当前已支持。

## 跨模块调用与事件

同步请求需要结果时用明确接口，例如支付、提交订单、生成实体。已经发生的事实用对局内事件/信号，例如研究完成、单位死亡、库存改变。一个模块不能把其他模块的内部字典当成公共 API。

UI 通过只读快照/展示模型观察；Model/Presenter/View 分离，避免 UI 反向查询整个场景树。每个订阅注明对局、实体或本地视图生命周期，退出时释放。

## 推荐落地顺序

1. 以移动和攻击验证请求、订单、行动、状态和表现链路。
2. 以生产/研究验证经济、科技与跨建筑队列查询。
3. 以英雄验证技能、状态效果、背包及专属 UI。
4. 完善感知边界，再扩展编队和战术/对战 AI。

验收应包括拒绝请求无副作用、取消后的资源释放、实体移除无残留订阅、对局重开、不可见信息不泄露，以及相同场景的性能回归。目录存在不等于功能完成。
