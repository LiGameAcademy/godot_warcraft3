执行顺序与可派发工作包见 [开发路线图](../roadmap/RTS_KERNEL_ROADMAP.md)：四批迁移细化为 M0–M7 八个里程碑；本文保留范围和验收依据。

## 1. 执行原则

按完整功能链迁移，每批可验证。先保持现有规则，允许已确认的固定步长与等价寻路差异；玩法优化另列 TODO。纯 C# 内核先直接验证，再接入 Godot，不能只凭画面运行宣布完成。

原方案的五个“替换 Node 入参”批次废止，改为下述四个功能批次。新增目录或无 Node 的签名不是验收依据；所有模拟必须在无 Godot 运行时成立。

混合运行期间每项状态只有一个权威。新内核负责已迁移状态，旧逻辑只能经桥接提交请求或消费镜像；若旧逻辑无法遵守帧边界，先在隔离验证场景推进完整功能链，不声称混合主游戏已确定性运行。每批记录可玩范围与尚未迁移的行为，不静默禁用功能。

快照/重放的中间验收限已迁移闭环；最终验收覆盖完整对局。旧实现只有在对应行为已有新测试、Godot 接入验证且引用清理后才移除；不永久保留旧路径开关。

## 2. 现有实现与迁移清单

以下路径相对仓库根，按源码检查建立；实施前需核对当前分支新增内容，并冻结测试与行为清单。

- `packages/gameplay/match/`：会话、库存、开局与胜负。进入内核，原 Node/全局访问转显式实例状态。
- `entities/state/`、`entities/commands/`：生命、身份、命令路由、订单队列、智能交互与巡逻。转换为稳定 ID、类型化订单与统一命令入口。
- `features/navigation/logic/` 与 `presentation/unit_navigator.gd`：寻路、落点分配、预约、避让、转向、坡度与移动。真实移动规则全部进入内核，保留 Godot 模型插值。
- `features/combat/`：攻击状态机、射程、伤害、弹道、死亡。保留表现目录中的受击闪烁、飘字、视觉弹道。
- `features/economy/`、`harvest/`：资源、携带、交付、树木、矿与采集状态；进矿和施工在场性同步迁移。
- `features/build/`：合法性、占地清场、施工策略、取消与工地生命。鼠标放置预览留在 Godot，内核再次校验落点。
- `features/production/`、`technology/`：训练、生成、集结点、已有科技与前置条件。不新增尚未实现的完整科技树。
- `features/abilities/`：施法、效果、Buff、法力、冷却、自动施法、被动与召唤寿命。按技能文档精简迁移。
- `features/heroes/` 及 abilities 中的英雄状态：经验、升级、技能点、死亡/复活相关既有行为。
- `features/items/`：物品实例、地面物品、拾取、背包、商店、掉落与使用。共用伤害/治疗/状态结算。
- `features/units/logic/militia_controller.gd` 与 `apps/game/app/units/unit_form_service.gd`：形态切换进入内核；模型更换留在表现。
- `features/ai/`：单位自动行为、队伍、玩家经济与军队 AI。现有逻辑完整迁移，不增强策略。
- `entities/presentation/unit.gd`、`features/interaction/presentation/`、HUD/选择/相机：保留表现职责，移除模拟权威。
- `apps/game/app/*_module` 对应装配代码：逐步改为宿主装配与视图连接，不再通过节点推进模拟。
- `packages/map/`、`packages/content/`：现有解析、加载和资产管线保留，仅新增内核数据转换。
- `integration/ability_system/`：目前治疗效果桥接需合并到统一 C# 效果服务；插件其余使用点含场景、资源、Autoload 必须另扫，不仅检索 .gd。

旧插件不要求双版本维护、API 对等或资源格式兼容。删除前检查源码、场景、资源、配置、测试与其他应用的实际引用；仍被其他用途使用的部分不能因本轮迁移而误删。

## 3. Batch 1：可独立运行的移动与战斗闭环

### 交付

- 锁定 Godot .NET、SDK、目标框架及构建方式；普通 .NET 内核、CLI 和测试工程可独立构建运行。
- 定义数据/地图数据转换、实体 ID 与生命周期、命令帧、统一时钟、随机流、事件及快照基本协议。
- 小地图中的移动、路径查询、预约/避让、攻击、追击、伤害、死亡和弹道；相关单位自动行为随链路迁移。
- C# 到 Godot 集中桥接，画面从内核状态更新，不用视觉回调结算。
- 移动中、攻击前摇中、弹道飞行中捕获并恢复快照；命令重放与双实例隔离测试。

### 验收门槛

无 Godot CLI 与 Godot 宿主在相同配置、种子和命令下产生相同内核状态；渲染帧率变化不改变模拟。不存在 Godot 程序集间接依赖。

小地图覆盖窄路、斜坡、障碍边角、不可达目标、不同单位尺寸、动态占地及目标死亡。与现有寻路比较可达性和路径质量，不要求等价路径逐点相同。

明确浮点精度、30 Hz 体验、持续时间换算、同帧系统顺序与出生/死亡语义。验证失败先修设计或实现，不盲目扩大迁移。

## 4. Batch 2：经济、采集、建造与生产闭环

### 交付

库存与人口、支付/退款、采金/伐木/交付、在场性、落点合法性、占地与清场、施工及取消、训练/出生/集结点、已有科技条件。玩家经济 AI 中相关命令随功能接入；未迁移决策可临时保留明确桥接。

### 验收

- 资源不足、目标失效、非法落点不留下扣费或占地残留。
- 多个订单争用资源、队列取消退款、建筑破坏、出生出口阻塞行为符合冻结基线。
- 人口预留与释放、进矿/出矿、施工结束、形态变化可恢复。
- 动态建筑阻挡影响真实寻路；不能只修改 Godot 可视节点。
- 采集途中、施工中及训练中读档与连续运行一致。

## 5. Batch 3：技能、英雄与物品闭环

### 交付

模板 + 效果组合 + 专用 C# 行为；Buff/属性修正/过滤统一，保留当前已实现的主动、被动、光环、开关、自动施法与召唤机制。迁移英雄成长、形态、背包、商店、掉落与物品使用。

新增技能 JSON 加载、Schema、语义校验、示例及开发说明；旧技能继续消费现有数据来源，归一化为相同定义。重复 ID 拒绝，不实现继承/覆盖/热更新。

### 验收

- 前摇、接近、引导、中断、失败费用、冷却与物品次数只由一个入口提交。
- 周期效果、叠加/刷新、驱散及属性恢复按既有支持范围回归。
- 技能测试覆盖治疗、弹道眩晕、暴风雪、召唤、传送、被动与自动施法。
- 引导中、多重 Buff、召唤寿命中途恢复，不重复执行效果或丢失状态。
- 非法 JSON 定位技能与字段，未知行为/状态引用被拒绝；同 ID 多来源被拒绝。
- 不依赖旧 AbilitySystem 的 Node/Resource/Autoload 完成模拟。

## 6. Batch 4：完整对局与旧路径退出

### 交付

剩余玩家军队 AI 与经济 AI、开局配置、队伍、胜负、重开、完整对局快照和命令日志。清理旧模拟、临时桥接及不再使用的插件引用。

### 最终验收

1. 完整无画面对局可在普通 .NET 进程快速运行，不加载 Godot；加速仅增加单位墙钟时间内的 Step 次数。
2. 固定初始状态、代码/内容/地图、环境与命令序列，重复运行逐帧校验一致。
3. 任意选定逻辑帧快照恢复，后续权威状态与连续运行一致，含 AI、队列与随机流。
4. 两场对局交错推进互不干扰；退出后重开无状态、订阅或适配请求泄漏。
5. 实际游戏输入、HUD、选择、相机、动画、音效及现有游戏流程回归。
6. 10 玩家配置正确；300/500 活跃单位性能验证完成，并报告附属实体数量。
7. game/editor 共享包加载和已有地图编辑工作流无回归；不要求编辑器新增内嵌对局功能。
8. 迁移清单中已有玩法全部覆盖；不能以删除旧测试替代覆盖迁移。

## 7. 测试与基准安排

### 场景

新建小型可重复地图数据夹具，覆盖确定性边界，不依赖大型美术资产。实际地图由实施阶段从当前能正常开局的地图选择，记录确切路径、内容版本与地图哈希；用户未指定地图，本轮文档不虚构已验证样本。

已有测试作为行为参考与 Godot 接入回归来源，例如：

- `tests/unit/selftest_navigation_module.gd`、`selftest_combat.gd`、`selftest_c_combat_projectile.gd`。
- `selftest_build_flow.gd`、`selftest_build_module.gd`、`selftest_tower_defense.gd`。
- `selftest_ability_blizzard.gd`、`selftest_ability_mountain_king.gd`、`selftest_ability_mass_teleport.gd`、`selftest_ability_autocast.gd`。
- `selftest_item_system.gd`、`selftest_match_session.gd`、`selftest_unit_selection.gd`、`selftest_ui_gameplay_bridge.gd`。

现有测试常直接构造 Node。迁移时将模拟断言移入 .NET 测试，保留 Godot 适配断言，记录旧测试到新测试映射。不声称现有测试在本次文档工作中已经运行。

### 性能

在同一机器、相同地图/内容、Release 构建、固定脚本场景下测量。先预热，再记录采样区间与重复次数。常规 300、压力 500 活跃单位；移动、密集混战、采集建造分别测量，不能只测静止单位。

记录内核单帧耗时中位数/P95/P99/最大值、寻路尖峰、内存与分配/GC、快照大小及恢复耗时；Godot 侧另记帧时间、同步转换耗时与显示实体数。

30 Hz 每逻辑帧总时间约 33.3 ms，但该值不是可全部占用的内核性能预算。具体毫秒门槛、可接受回归比例及余量在 Batch 1 实测后冻结；未冻结前不得宣称性能达标。500 是测试目标，不是由人口推导出的硬实体上限。

## 8. 风险与待验证事项

- K-001：确认 .NET/Godot C# 工具链、工程引用及共享包同步；禁止仅凭程序集名称跳过验证。
- K-002：纯 C# 寻路与 AStarGrid2D 的可达性、等价路线、动态更新成本；必要时调整算法，但保留契约测试。
- K-003：double、固定帧计时和系统阶段带来的行为差异；冻结同帧语义后再迁移全量技能。
- K-004：明确现有各状态实际写入者，防止旧 AI/节点 meta 反写已迁移状态。
- K-005：检查快照遗漏的隐含状态，包括分离预约、AI 倒计时、随机流、待执行命令及运行中的技能。
- K-006：性能基线与门槛；关注大量同帧寻路、被动扫描和跨语言数据转换。
- K-007：旧插件引用退出及资源格式使用点审计，避免其他应用或测试失效。
- K-008：真实地图、功能/测试映射与代码版本清单在实施前锁定。

上述条目是实施验证门，不是待用户再次选择的架构问题。出现需要扩大范围或改变已确认玩法的结果，再提出明确决策。
