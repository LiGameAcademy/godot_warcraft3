# 仓库目录与文档边界

开源仓库保存运行源码、可复现工具、测试、工程设计及维护记录。课程文稿、视频字幕、录制计划、营销文案和发布素材放在仓库外的教学资料目录；公开文档不能依赖这些本地资料才能阅读或运行。

## 目录职责

- `apps/`：游戏、地图编辑器、资产查看器三个独立 Godot 应用及各自的装配代码。
- `packages/`：foundation、content、map、gameplay 等共享源码。
- `addons/`、`external/`：第三方插件及独立维护的 RTS 内核依赖。
- `content/`、`examples/`：内置内容定义及示例。
- `assets/`：资源管线工作目录；转换资产遵守忽略规则及资源使用政策。
- `tools/`：资源处理、工作区同步、构建与验证工具。
- `tests/`：测试源码；手工验收步骤在 `docs/test-cases/`。
- `docs/`：公开工程文档。
- `tmp/`、`logs/`、`.cache/`：本地临时产物。
- `output/`：工具输出；视频发布素材不在此长期维护。

共享源码只在 `packages/` 修改，应用内由同步工具生成的副本不手改。目录调整必须同步更新资源路径、UID、工作区映射和测试入口。当前已经完成产品与共享包分离，不为统一命名再次搬动运行源码。

## 文档归类

- `architecture/`：跨模块依赖、状态归属、目录迁移决策。
- `design/`：按子系统组织的设计与实现约定。
- `data/`：数据格式、资产来源、转换和资源使用边界。
- `roadmap/`：工程计划、阶段目标和验收进度。
- `tests/`、`test-cases/`、`verification/`：自动测试说明、手工验收及专项验证记录。
- `dev-log/`：可公开的技术变更记录，包含问题、实现、验证和限制。
- `tools/`：工具相关工程文档。

“开发日志”是否保留取决于内容用途：提交与验收记录属于工程资料；口播、选题、课程讲义、植入广告、截图剪辑方案属于教学出版资料。原创玩法与世界观设计仍属于项目设计，不因尚未落地而自动移出。

## 提交前检查

运行 `node tools/check-docs-links.mjs` 检查文档链接，使用 `git diff --cached --name-status` 核对实际暂存清单。

`.gitignore` 只阻止未跟踪文件被常规添加，不会移除已经跟踪的素材。移出已跟踪文件需要单独检查删除差异并提交；以前提交的内容也不会因此从 Git 历史消失。教学目录独立备份，不依赖开源仓库保存。
