# 魔兽地图编辑器目标与验收基线

更新：2026-09-13。目标仍在执行；本文件不代表整体完成。

## 完整目标

以当前 Godot 4 项目已有的魔兽争霸 3 原版导出数据和资产为基础，分阶段实现可实际使用的地图编辑器，完成创建地图、编辑地形、放置对象、配置属性、保存、重新加载和运行预览的完整流程，逐步接近原版操作方式与视觉表现。

保留原始对象 ID、属性和资源关联；复用现有架构；缺失资源、未支持字段和功能必须明确提示。每阶段交付可运行成果、说明、重复验收步骤和已知差异。首阶段不要求完整战斗系统、全部原版功能或 w3m/w3x 原生格式兼容。性能必须在固定环境和固定样例上测量。

## 本轮修复与验证

工具面板和新建地图窗口原来在 tscn 中直接引用 converted PNG，而该目录使用 .gdignore。启动出现 No loader found 和场景资源解析错误。已将原版逻辑路径保存在控件 metadata，运行时通过 RuntimeAssets 加载纹理，缺失图标提供路径提示；笔刷尺寸图标也改为运行时读取。

环境：Windows，Godot 4.6.3 stable，项目配置 Forward Plus / D3D12。本轮为 headless 检查，不能作为图形性能或视觉验收。CPU/GPU 查询受当前环境限制，尚未建立硬件性能记录。现有 GODOT_PATH 与 Godot MCP 指向不存在的旧路径，实际使用桌面的 4.6.3 console 程序。

可重复命令（仓库根目录 PowerShell）：

```powershell
$editorGodot = 'C:/Users/Administrator/Desktop/Godot_v4.6.3-stable_win64_console.exe'
& $editorGodot --headless --path . --log-file ./logs/editor-goal-baseline.log --script res://tests/unit/selftest_editor_commands.gd
& $editorGodot --headless --path . --log-file ./logs/editor-goal-smoke-fixed.log --quit-after 120 res://editor/scenes/editor_main.tscn
```

- 地表笔划撤销/重做测试 PASS，退出码 0；测试初始化阶段有 DefStore 不可用的警告。
- 修复后编辑场景成功创建 64×64 洛丹伦（夏）地图，退出码 0；日志无场景解析、贴图加载或脚本错误。
- 两次运行仍报告 Failed to read the root certificate store；不能将退出码 0 表述为日志完全无错误。
- 尚未进行真实窗口交互或截图验证，未验收图标视觉、地形观感与鼠标操作。

## 首轮发现的闭环缺陷（历史记录）

1. `MapDocument.save_json()` 默认写入 user://editor_maps 下带时间戳的文件，但主体只有高度图；新建地图的对象、info、pathing 未随之保存。
2. 对导入地图调用保存时，对象文件可能写回原始 map_dir，与另存的地形文件分离；对象写入错误也未传递。后续回归必须使用隔离的源目录副本，不能对原始示例执行破坏性实验。
3. 打开入口读取解析地图目录，没有与当前保存格式匹配的打开用户地图入口。
4. 保存后小地图导出依赖 map_dir，新建图会提示部分失败；应将地图保存与可选小地图导出结果分开处理。
5. `file_test_map` 有菜单 action，但总管没有对应处理；必须以当前编辑文档启动预览，不能以固定 Echo Isles 代替。
6. 导入无效高度图、缺失对象文件及未知字段时，完整性和事务性未验证。要求加载失败保持原文档、保存失败保留脏标记与已有有效存档，未知数据保留或明确拒绝。

本轮后续已完成：完整地图单文件 v1、临时文件提交、加载校验及失败保留当前文档、未知字段保留、保存/另存为与文件打开入口；取消保存时自动写回源目录小地图。存储回归 0 failures，地表命令测试 PASS，编辑器启动无新增脚本/场景错误。详见 [格式与验证](../design/editor/MAP_FILE_FORMAT.md)。

后续预览阶段：已加入未保存内容切换确认、当前文档独立窗口视觉运行预览，headless 与实际 D3D12 渲染集成测试通过。详见 [预览说明与证据](../design/editor/MAP_PREVIEW.md)。

对象阶段：已按原版 texID/texFile 修复夏树纹理；单棵、批量和面板预览共用替换逻辑。单位/装饰物各十轮增删改撤销重做通过，详见 [对象验收](../design/editor/OBJECT_ACCEPTANCE.md)。

导入阶段：六张地图校验通过，损坏/缺失核心文件保持当前文档；缺失可选 pathing 明确警告并随存档保留。导入回归和单文件回归均 PASS。

性能阶段：已建立 [真实渲染性能基线](../design/editor/PERFORMANCE_BASELINE.md)。小图编辑 CPU 重建 P95 514 ms、大图 7,667 ms，未满足响应目标；不能因浏览约 60 FPS 而标记通过。

纹理优化阶段：纯地表纹理局部更新与完整重建数组对照通过，笔刷及撤销/重做已接入。同样例 CPU 更新约 0.5 ms；包含小地图刷新的回调小图 43 ms、大图 599 ms。详见 [局部更新](../design/editor/TERRAIN_INCREMENTAL.md)。

高度阶段：发现五个高度按钮此前仅改变面板状态，现已接入实际笔刷、文档与撤销重做。升高/降低每次笔刷采样改变 16 个原版高度单位；平整使用笔划起点相对悬崖层的高度，平滑对同层邻点平均值做半步插值，噪声在 ±16 内变化。仅修改地表高度，不修改悬崖层和水面。算法自测以及编辑器面板信号、笔刷入口、撤销重做、保存重开的集成测试均 PASS（0 failures）。高度编辑目前仍触发完整重建；连续按住原地累积、真实鼠标交互、视觉及性能仍待验收。

仍待推进：真实窗口保存/打开验收、对象界面操作及资源级缺失诊断、其他原版视觉差异、高度/悬崖/斜坡更新、大图初次构建与完整性能复验。上述历史缺陷已有部分修复，不能据此将完整闭环视为通过。

## 验收样例与门槛

现已生成可直接打开的 [四类对象样例与复验步骤](../../examples/editor/README.md)，地图为 `examples/editor/acceptance.wc3map.json`，包含 hpea、htow、LTlt、LRrk、两种纹理及升高草地。通过面板信号和笔刷接口生成后，保存、重开及 D3D12 预览断言通过，截图确认四类原版模型同时显示且占位计数为零。仍需完整人工界面复验；不能将脚本操作入口的测试替代操作系统鼠标事件验收。

最小编辑样例指定 64×64 洛丹伦（夏）空白图；地表至少两种，包含高低地形，放置 hpea、htow、LTlt 以及目录中实际可加载的一种装饰物。这些 ID 的目录/模型可用性需在样例生成时核验，缺失必须记录，不能用占位模型声称原版资产通过。保留原始导出地图不变；Echo Isles 作为导入规模对照。
