# 经典 Warcraft III 与地图编辑器：成果验收草案

> 当前范围已按用户最新目标调整为 **EI 1v1 MVP**，以 [EI_MVP_ACCEPTANCE.md](EI_MVP_ACCEPTANCE.md) 为准。以下完整编辑器/四族/战役路线图保留作历史规划，不再作为当前MVP的完成门槛。

日期：2026-09-13。状态：目标草案，以下项目均不代表已验收。

## 1. 总目标与范围

使用 Godot 4 实现可独立运行的经典 Warcraft III 玩法与地图编辑器，形成「制作地图 → 测试 → 打包 → 单机/联机游玩 → 回放与排错」的完整流程。在有证据的基础上修复缺陷，谨慎改进体验和扩展能力。

建议以经典美术风格、冰封王座四族对战为首个完整版本范围；混乱之治及冰封王座战役作为后续完整复刻里程碑，不从长期目标中删去。具体经典补丁版本尚未确定：数值、机制、数据及对照客户端必须统一到一个明确版本，不能混用多个版本的行为。

首个完整版本不以官方在线服务互通、原版二进制回放互通、所有历史自定义地图无修改运行为门槛。这些兼容能力单列验收，不能由“支持导入地图”推导出来。

延续仓库现有资产管线与分发约定，不把本地转换出的游戏资产纳入源码交付。

## 3. 游戏本体覆盖清单

- [ ] 操作：点击/框选、编队、追加指令、智能右键、移动、攻击移动、停止、保持、巡逻、集结点、快捷键及相机。
- [ ] 经济与生产：金木、人口/维护费用、建造/修理/取消退款、生产队列、科技前置、升级与种族特有经济机制。
- [ ] 战斗与寻路：攻击类型/护甲、伤害结算、索敌/仇恨、弹道、碰撞、体型、地面/空中通行、动态阻挡及拥挤下的命令响应。
- [ ] 英雄与技能：经验/属性/升级、技能点、魔法/冷却、施法前后摇与打断、自动施法、召唤、光环、Buff/驱散、死亡与复活。
- [ ] 物品与中立内容：拾取/丢弃/转交/购买/出售/使用、背包限制、掉落表、商店库存/补货、雇佣与中立建筑。
- [ ] 世界规则：战争迷雾、探索黑幕、昼夜/视野、隐身/侦测、地形通行、树木破坏及野怪营地行为。
- [ ] 对局：玩家/队伍/联盟、出生配置、电脑难度、胜负判定、结算、暂停及单机存档读档。
- [ ] 表现与反馈：动画、玩家色、选中提示、血蓝/Buff、命令反馈、声音、特效、小地图、菜单和设置；不泄露迷雾中的敌方信息。

每项均按“数据覆盖 + 实际行为 + 界面反馈 + 边界用例”验收。目录里存在模型或技能定义不等于功能完成。

## 4. 编辑器覆盖清单

- [ ] 地形：纹理、高度、水、悬崖、斜坡、地图边界、通行层可视化；显示与游戏寻路一致。
- [ ] 对象：单位、物品、装饰物、可破坏物、区域、相机、出生点；支持选中、多选、移动/旋转/缩放、复制/粘贴及属性编辑。
- [ ] 地图设置：尺寸、地形集、玩家/队伍、初始资源、地图说明、环境和胜负规则。
- [ ] 物体编辑器：单位、技能、Buff、物品、建筑、科技、装饰物与可破坏物；支持继承、覆盖、搜索、字段校验及引用检查。
- [ ] 触发器：事件—条件—动作、变量/数组、函数、计时器、区域与对话等基础能力；报错能定位到地图和触发器。
- [ ] 脚本与调试：明确语言及支持范围，提供日志、变量检查与执行保护；脚本失控可终止并定位。
- [ ] 资源管理：导入、预览、依赖与缺失提示、相对路径和打包；换机器打开不依赖作者电脑的绝对路径。
- [ ] 工作流：新建/打开/保存/另存、撤销重做、自动保存与恢复、启动测试、版本迁移与打包。

必测：连续 100 次混合编辑全部撤销后，语义数据等于编辑前；重做后等于编辑后。保存失败不覆盖最后一份有效地图；恢复流程用人为中断验证。

## 5. 原版兼容单独验收

| 层级 | 范围 | 验收方法 |
|---|---|---|
| C1 地图数据导入 | 地形、对象、玩家设置等明确支持的字段 | 固定样本逐字段对比；未知字段或不支持内容给出报告，不能静默丢弃 |
| C2 对象与玩法语义 | 自定义单位、物品、技能及数值 | 固定场景对照基准版本，核对行为和数值；近似实现登记差异 |
| C3 脚本兼容 | JASS/GUI 触发器及所依赖的原生函数等 | 先列支持矩阵，再测试有代表性的地图；仅通过明确清单时声称兼容 |
| C4 原版地图导出 | 写回约定的原版格式 | 导出后由目标版本编辑器打开并运行；未实现前只承诺项目原生格式保存 |

自定义地图兼容率必须写成“固定样本 N 张，通过 X 张”，附版本和失败原因，不能笼统承诺全部兼容。原版回放和在线服务协议各自另立目标。

## 6. 修 BUG、改设计、加功能的边界

采用有版本号的规则配置：经典基准配置用于对照，改进配置承载影响玩法的变更。地图、存档、房间和回放记录配置版本；不允许不同规则混入同一对局。崩溃、数据损坏等工程缺陷直接修复，不要求保留故障模式。

| 类别 | 候选内容（不是已经确认的原版 BUG） | 纳入标准 |
|---|---|---|
| 缺陷修复 | 寻路卡死、命令丢失、状态残留、存档损坏、同步分歧 | 原版缺陷先有基准复现证据；项目自身缺陷有最小复现；修复附回归用例及影响范围 |
| 体验改进 | 自定义快捷键、界面缩放、搜索筛选、批量编辑、自动保存、错误定位 | 具体任务能减少操作或避免错误；默认值可解释；不改变隐含战斗规则 |
| 谨慎扩展 | 更大选中规模、队列便利操作、更高地图/单位上限、新脚本接口 | 独立开关或规则版本；明确兼容影响、性能成本和收益；影响平衡的改动经对照试玩 |

寻路“更聪明”、自动施法更积极、去掉操作限制等可能改变围杀、微操和节奏，不能仅凭“不方便”判定为坏设计。新种族、新兵种及重做平衡先作为扩展内容，不占据复刻主线的完成标准。

## 7. 质量门槛（初始建议值）

以下数字是待实际测量校准的目标，不是当前性能承诺。M0 固定参考机器、分辨率、画质、地图尺寸、单位数量口径及模拟频率。

- 正确性：所交付范围的必测用例全部通过；阻塞启动/通关、崩溃、数据损坏、作弊式信息泄露及联机分歧为 0 个未解决项。
- 性能：参考机器在 1080p、约定标准画质、200 个活跃单位的固定战斗场景中，10 分钟采样帧时间 P95 ≤ 16.7 ms；另测 500 单位压力场景并记录瓶颈。
- 稳定性：游戏持续对局/循环模拟 2 小时、编辑器持续混合操作 2 小时，无崩溃或持续无界内存增长。
- 确定性：固定地图、种子和命令序列重复运行 10 次，逐模拟检查点权威状态哈希一致；联机在支持的平台组合上验证。
- 网络：建议覆盖 0/100/200 ms 往返延迟、30 ms 抖动与 1% 丢包场景；每组完成 30 分钟对局，无分歧和永久卡死，记录命令响应。
- 保存：至少 10 个不同进度检查点，保存/读取后权威状态与继续模拟结果一致；覆盖计时器、随机数、技能、生产队列及脚本状态。
- 编辑器响应：约定标准地图普通笔刷操作反馈 P95 ≤ 100 ms；较慢导入/构建提供进度及可诊断结果。
- 发布：源码版本、构建说明、资源准备说明、规则/地图格式版本、测试报告和已知问题均可追溯。

## 8. 每次验收的证据

统一记录：需求编号 → 基准版本/规则配置 → 前置条件和固定输入 → 预期结果 → 实际结果 → 测试日志/截图/录像/状态对比 → 通过或失败 → 关联缺陷。

状态使用“未开始 / 实现中 / 待验收 / 已通过 / 有限支持”。已有文档打勾仅作为核查线索；没有当次验证证据不直接标为已通过。

## 9. 当前项目的落点

本次只审阅 README、ROADMAP、NEXT、TODO 与测试索引，未启动游戏，因此不对现有功能作通过判定。文档显示已有资产转换、地图地形、人族玩法和技能系统基础；工作区另有 AI、物品及表现相关未提交改动，应先核查后更新状态。

推荐下一批实际交付：

1. 固定经典补丁基准，并核实现有 N0/N1 与物品/AI 工作的真实完成度。
2. 完成 M1 的“从开局到胜负结算”固定剧本，留下首次可重复验收记录。
3. 完成 M2 的“从空白图到可打一局”剧本，验证编辑器和游戏共用同一份地图语义。
4. 在两条闭环稳定后扩展四族和触发器，同时持续验证确定性与存档能力。

这份文档定义长期成果；NEXT.md 继续承担近期任务排序。本文不替代各模块设计，也不自动将新功能全部提升为当前优先级。
