日期：2026-09-27。对应 [执行策划案](UNIFIED_IMPORT_EXECUTION_PLAN.md) 的阶段 A 和用户追加的独立资产查看器。阶段 B/C/D 的保真改造、原作对照和百单位性能验收尚未完成。

## 本轮实现

- 新增 `tools/asset-convert/src/audit-cli.mjs`，可全量扫描源与转换产物、独立记录失败、缓存源解析结果并重复执行。不会改写原始文件或现有 `.scn`。
- 每个模型记录来源及内容哈希、MDX 块、源特征、依赖、导出能力对照、分类理由、风险等级、实际产物路径和未验证状态。已记录当前解析器版本和相关管线源码哈希。
- 直接对照 PE2、Ribbon、TextureAnims、GeosetAnims 的源数量和 sidecar 数量；其余特征本轮主要完成枚举，显式标为未比较／未验证。数量匹配不是关键帧和值完全保真的证明。
- 生成 `report.json`、按影响模型数排序的 `tasks.json`、`summary.md` 和代表样本。运行输出位于本地 `.cache/asset-audit/latest/`，不提交衍生资源。
- 新增 [资产查看器](../../../apps/asset_viewer/README.md) Godot 项目，共享 foundation/content/map；支持查找筛选、动画、暂停重播、队伍色、相机、地面／背景和审计诊断。两产品原有加载流程未在本批次切换 profile。
- 光晕首版按用途写入节点分类元数据：`hero_ground` 使用保持深度测试的地面 shader，`weapon_socket` 使用挂点 billboard shader，无法判定时保留 `floating_orb_fallback` 或 `unclassified_team_glow`；这仍需原作游戏内视觉验收。
- 工作区同步、布局检查、PowerShell 启动验证和 Python 测试入口已纳入第三个应用。

## 扫描范围与结果

范围是本机 `.cache/wc3-assets` 的全部可访问模型，加 `assets/asset-converted` 的转换模型清单。来源清单为 `.cache/manifest.json`，解包时间记录为 2026-08-09；解析器为 war3-model 4.0.1。本轮发现的模型均有源文件，源解析全部成功。

- 3,289 个模型；3,287 个有 `.scn`；2 个尚无 `.scn`。
- 最高风险等级：P0 276 个、P1 1,751 个、P2 38 个；1,224 个没有命中当前规则。没有命中不等于已经通过保真验收。
- 1,432 个模型的相关导出描述缺失或数量与源不一致。其中 Ribbon 146 个、纹理动画 71 个、GeosetAnim 1,387 个；这些集合有重叠。PE2 发射器数量本轮没有发现不匹配，但动态参数仍有已知简化风险。
- 274 个 glTF 存在缺失或无效的外部依赖；45 个模型引用的源纹理与对应转换纹理均未找到。P0 条目表示生成／重建链路风险，不代表这些模型当前的 `.scn` 一定无法显示。
- 源特征风险包括：多层材质 760 个、材质层动画 641 个、动态 PE2 参数 284 个、纹理动画 72 个、Geoset 颜色轨 69 个、Ribbon 148 个。
- 528 个模型使用 ReplaceableId=2 队伍光晕纹理，496 个模型的逻辑路径可能触发当前 Presenter。前者不全是英雄地面光晕；后者只是路径候选，不代表全部实际被替换。

同一问题在同一模型内只计一次，不同问题的模型集合可以重叠。本轮没有取得和完成原作游戏内视觉对照，视觉已验证数为 0。也未证明当前 loose 文件目录覆盖经典客户端全部 MPQ 内容；清单记录获胜来源包，但不包含完整覆盖历史或可靠客户端补丁版本。

## 下一批执行顺序

1. **确认并修复旧产物的重建链路。** 从 DarkPortalTarget 的 `./DemonRune1backup.png`、InnerFireTarget 的 `./Crown1.png` 等错误引用着手，检查现有 URI 修复工具和当前转换器行为。对导出数量缺口先用现有转换器在小样本上重新生成，区分旧 sidecar 与仍存在的导出缺陷。验收要求依赖可解析、源／导出数量对照正确、重新 bake 和磁盘重载成功。
2. **阶段 B：保真和增强分离。** 对 `map_model_cache.gd`、`wc3_fx_presenter.gd` 及 Fireball 专项处理建立显式 profile 契约，检查 visuals 和 fallback 优先级，缓存签名包含 profile。查看器届时才能提供真实的两模式对比。
3. **补齐共性数据与消费能力。** 针对动态 PE2 参数、材质层／纹理／Geoset 动画逐项贯通源、sidecar、Godot 消费及重载测试。保留原始轨数据，不能用增加亮度补偿缺失的时间变化。
4. **分类重构光晕。** 队伍光晕先按节点、材质、挂点和原作用途分型；英雄地面、武器和其他光晕分别定义深度、朝向、颜色与生命周期。低置信度项保留待复核标记，不默认套用通用软圆。
5. **扩大真实游戏对照及性能测试。** 先用固定样本验证，再扩大 bake 范围；百单位场景需独立建立，当前查看器截图不是战斗性能或原作保真验收。

以上批次应复用审计报告中的模型集合和问题 ID，每批修复后重跑对应检查并比较问题数量。当前脚本退出成功仅表示源解析没有失败，质量门槛必须读取报告。
