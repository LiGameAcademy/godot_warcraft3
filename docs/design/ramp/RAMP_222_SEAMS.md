# 222 斜坡裂缝：原因、修复及完整性边界

2026-09-14。用户原文件只读，原样保存为 tests/fixtures/editor/ramp-user-222.wc3map.json（65×65 顶点，12 个坡旗）。

## 实际原因

222 收集出 BHLA@(27,26)、ABHL@(29,26)、AAHL@(28,30)，但完整入口仅 (29,29)。BHLA 的 (28,27) 和 ABHL 的 (30,26) 为坡体半层中点：原版模型要求 -64 WC3，而原始层高为 1，对应 -128 WC3。现有只根据完整四角入口生成抬高的算法未覆盖这两个点。坡体与地面/直崖分别计算边界，形成 64 WC3 的高度差。

111 修复仅处理“直崖靠入口地面”，未处理整个 CliffTrans 周界，也未统一坡体中点高度；它是覆盖不全的修复。旧可见格测试检查的是单元存在性，不能证明几何无缝，所以 222 修复前也会报 coverage PASS。

## 本次实现

新增 wc3_ramp_seam_plan.gd，合并入口抬高与实际已解析坡体的低侧中点抬高（幂等 +64），生成共享接缝区域。地面、直崖、坡体使用同一份规则。CliffStitcher 仅处理模型外周，内部网格线不调整；周界沿共享网格高度作分段线性对齐。原模型内部顶点、UV、索引不变，不插入遮洞平面，不修改用户保存层高或坡旗。邻接包含角点的对角接触。修改后的坡体使用新包围盒。

这是适配本项目允许不完整坡旗组合的扩展，不是 HiveWE 源码完全照搬。原版岩石边缘会局部变形，周界接缝策略与保留所有原版边缘形状存在取舍。

## 如何接近彻底解决

推荐以原作兼容为目标，定义有限合法坡形及层差约束；每次笔刷编辑先在邻域求解可满足的坡旗/层高组合，不能满足时明确拒绝或显示未成形预览。已有地图加载时报告不满足约束的位置，不静默改用户数据。

建立统一地形构建结果，明确每个单元由地面、坡体还是直崖拥有，共享边只定义一次。几何验证应检查两个方向：缺面/重复覆盖，以及共享折线在两侧顶点并集处的高度一致；另外检测退化三角形、非流形边和重叠面。覆盖转向、加宽、擦除、相交、自由高度、多层悬崖、地图边界、保存重开与随机连续笔刷序列。

当前只有来源组合测试和用户场景回归，尚没有完整的合法状态求解器与上述通用网格审计。尤其多层直崖叠段、相交坡体及任意自定义模型不在“已保证无缝”的范围内。若要允许完全任意坡形，则应采用统一程序化地形网格，并承担原版模型外形/UV 忠实度的取舍；不能只靠有限原版模块和补旗逻辑作绝对保证。
