# 斜坡架构与后续实现约定

更新：2026-09-14，第三轮：有限原版支持 + 连通区域保底。本文是当前实现入口；REFACTOR_ITERATION_1/2 保留历史阶段记录。

## 目标与原因

裂缝不仅来自某一种四角形状，还来自地面、直崖、CliffTrans 对同一条边的高度和覆盖范围理解不同。逐个增加特殊模型不能消除这类分歧。当前方向是统一构建计划、明确每格表面归属、共享边界高度；复杂组合由保底区域承担。

435 是四角层高 0..3 与坡旗的 4096 种输入经过旋转、镜像和高度平移归并后的数量，不是 435 套手写算法，更不是所有邻域组合的总数。穷举用于检验分类完整性；模型是否可用仍须结合邻域与资产证据。

## 支持与处理规则

|输入或上下文|当前处理|
|---|---|
|无坡旗、无模型覆盖|基础地形|
|有已解析原版模型，模型覆盖全部角点层差恰为 1，且没有覆盖重叠|原版模型候选；若所属区域需要保底则一并替换|
|单层、满足 HiveWE 入口条件、没有模型覆盖|正常带纹理地表入口|
|完整四角坡旗，交叉鞍形或跨多层，未获原版支持|保底种子|
|原版模型覆盖重叠，或覆盖角点层差不为 1|保底种子|
|不完整坡旗、平地残留坡旗且没有模型支持|保持基础地形，记录 INVALID；不自动补旗或清旗|

这里的原版支持是保守的准入条件，不是已证明所有直坡、转角及其邻域都正确的形状白名单。模型识别仍由既有 Collect 与 Catalog 完成。INVALID 表示不能独立形成完整斜坡，并不表示地图文件损坏。

## 构建流程与职责

1. `wc3_ramp_cell_state.gd` 负责局部形状归并及初始处理分类，不生成网格。
2. `wc3_ramp_seam_plan.gd` 生成入口和模型接缝共享的角点 boost；不写回地图数据。
3. `wc3_ramp_surface_plan.gd` 汇总模型覆盖、地面挖空、入口、分类原因和区域替换结果。
4. `wc3_ramp_regions.gd` 对已支持或待保底的有效坡格做八邻接连通划分。共享角点也有接缝依赖；普通地形和无模型支持的不完整旗不参与扩散。
5. 含任一保底种子的整个连通分量转为地表；清除这些格的 dig，添加 ground_tiles，移除覆盖它们的完整原版模型及对应直崖。
6. `MapBuildContext` 缓存一次构建计划，Terrain / Cliffs / Ramps 消费同一结果。

`fallback_regions` 保存每个区域的 cells 与外边界边列表；边列表不是排序后的多边形。`original_placements` 是最终允许挂载的模型。`cells` 保存 canonical state、route、reason、owner 和保底 region；`routes` 每格只统计一次。`entrances` 保留源入口语义，`ground_tiles` 则包含最终实际显示的入口与保底地面，不可混用。

## 边界与纹理约定

区域内部仍复用现有逐格地表三角化器与地表材质，不是新建一个全区域共享索引网格。相邻地表格从同一角点高度与 boost 取值。即使原模型退出挂载，也保留已计算的接缝 boost，使边界高度计划一致。

外侧直崖/原版模型通过 CliffStitcher 对齐周界高度，保留源 UV、索引、材质和内部顶点，不修改缓存中的原始模型。保底使用正常地表纹理，目标是稳定连续，不能宣称与原版 CliffTrans 的造型和纹理完全相同。

必须保持：模型只能完整保留或完整替换；保底格必须恢复地面且不能同时保留该格直崖；构建不得改写保存的层高或坡旗。现有 romp 仍是采集器的过渡语义，不代表最终挂载模型集合；新增逻辑应以最终 plan 判断表面归属。

## 下一轮扩展门槛与限制

新增一种原版支持，应同时加入其旋转/镜像、连续绘制与擦除、相邻模型、区域边界的回归用例，再收窄保底范围。优先增加已遇到的地图样本，不为 435 个局部状态逐个编写模型补丁。

尚未完成任意邻域的封闭性证明。复杂多层直崖的周界投影可能压扁局部几何；还需审计退化面、边界采样不一致和 T 接点。八邻接保底也可能牺牲较大相连区域的原版造型，这是当前保守取舍。后续可用经过验证的边界契约拆分区域，不能直接改成单格替换。

后续应建立自动组合地图与区域外边界几何审计，加入地图边缘、连续撤销/重做及贴图检查，再验证拾取、碰撞与游戏通行数据的一致性。本轮没有新增通行规则，不能仅凭可见坡面推断单位可以通过，也不能将当前有限测试表述为“一劳永逸”。
