# 对战卡顿排查与首轮优化（2026-09-21）

## 测量范围

用户反馈：默认对战体验卡顿，条件尚不明确，疑似随对战时间增长而恶化。

以现有工作树为起点，不覆盖其他功能修改。性能前后对比使用同一 Godot 4.6.3 console 可执行文件、Echo Isles、固定起始位置。热路径测试关闭电脑决策，在地图就绪后暂停世界，选中大法师，各路径先预热 5 次再采样 120 次；场景单位层共 109 个子节点。

**以下是 headless CPU 测量，不是 GPU 或游戏 FPS。** 全单位邻近查询是逐个查询整层单位的压力样本，不等于真实每帧一定执行同样数量的查询。机器上另有编辑器/应用运行，绝对时长有环境噪声。

## 确认的热点及修改

| 路径 | 修改前平均 / P95（ms） | 修改后平均 / P95（ms） |
|---|---:|---:|
| 选中 HUD tick | 0.769 / 1.027 | 0.128 / 0.180 |
| 血条帧更新 | 3.944 / 5.464 | 1.969 / 3.102 |
| 血条成员与挂点同步 | 5.522 / 6.598 | 1.331 / 2.660 |
| 整层单位逐一查询邻居 | 30.456 / 46.465 | 7.527 / 10.238 |

### 攻防图标

`SelectionHudModule.tick → refresh_buff_strip → UnitCombatStatChip.set_stat → RuntimeAssets.load_texture` 每帧发生；最后一个方法会读盘、解码图像并创建新纹理。

修改：控件记住上次图标路径，数值变化复用原纹理。清空后重新选择仍加载图标；切换为空路径会清掉旧图标。缓存只存在于控件，不增加全局资源生命周期。

### 血条挂点及包围盒

原实现每 15 帧对所有单位重找挂点；没有挂点的单位还会每帧递归搜索并计算网格包围盒。屏幕外血条也进行位置和样式更新。

修改：缓存挂点解析和回退高度；`Model` 更换或旧挂点销毁时重新解析。没有挂点时每秒重试，以支持延迟装载；期间使用缓存回退高度，因此异步新增的挂点最多延迟约 1 秒被发现。已绑定挂点的坐标仍逐帧读取，跟随动画。屏幕外隐藏血条与名字，避免继续更新样式。成员同步改为每 0.25 秒，刷新频率不再随 FPS 改变。

### 邻近单位查询

原实现先为每个候选读取 metadata、检查在场性并查询建筑类型，最后才判断距离；大量远处单位重复进入较昂贵的类型查询。

修改：先按当前位置平方距离剔除远处单位，再执行原筛选。仍保留结果顺序、半径边界、自身排除、建筑开关与在场性规则；没有帧缓存，因此同帧移动/离场立即可见。算法仍是线性扫描；更多单位时可继续考虑带可靠失效机制的空间索引。

## 回归

- `selftest_match_hotpath_cache.tscn`：77 项通过。覆盖图标复用、清空与恢复、负挂点缓存、延迟模型、模型替换、动画坐标、同帧移动/离场、建筑过滤。Godot 4.6.3 与当前编辑器使用的 4.7.2 均通过。
- `selftest_group_move.gd`：通过，保护编队落点、间距与退化分配。
- `selftest_hero_life_game.tscn`：23 项通过，保护完整地图中的英雄生命周期及 HUD。

未改变战斗 tick、AI 决策频率、单位移动精度或画质配置。

## 两分钟持续对战观察

以 `--fixed-fps 60` 运行 7200 帧，电脑经营和军队均开启，前后两次均完成且日志无脚本错误。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 10 秒时单位层子节点 / 总节点 | 110 / 4649 | 110 / 4649 |
| 120 秒时单位层子节点 / 总节点 | 115 / 4863 | 115 / 4863 |
| 10 秒静态内存 | 459.46 MB | 459.41 MB |
| 120 秒静态内存 | 465.60 MB | 465.53 MB |
| 120 秒对象数 / 孤立节点数 | 22378 / 444 | 22378 / 444 |

修改后各 10 秒区间的每帧墙钟均值为 28.75–33.73 ms；修改前为 35.72–72.24 ms。**持续测试用于观察趋势，不据此承诺整体提速比例**：其他应用负载未隔离，修改前运行期间也穿插了少量验证进程。对热点优化收益优先参考上面的暂停世界微基准。

两次节点/对象数量走势吻合，末尾内存接近。样本内没有出现明显的对象爆炸；这支持“当前修改减少重复工作而非减少游戏对象”的判断，但不能排除更长时段的泄漏。孤立节点在新模型加载时阶梯增长，与模型缓存可能相关，尚未将其判定为泄漏或证明全部正常。

## 复现方式

```powershell
# CPU 热路径；以场景入口运行，不使用 -s。
& $env:GODOT --headless --path . res://tests/integration/benchmark_match_hotpaths.tscn

# 2 分钟模拟：固定 60Hz 时间步，开启电脑经营与军队，输出每 10 秒状态。
# 实际墙钟耗时取决于 CPU；不能把 headless 输出当作实际游戏帧率。
& $env:GODOT --headless --fixed-fps 60 --path . res://tests/integration/benchmark_match_hotpaths.tscn -- --soak

& $env:GODOT --headless --path . res://tests/unit/selftest_match_hotpath_cache.tscn
```

`MATCH_SOAK` 记录单位层子节点数、总节点数、对象数、孤立节点数、静态内存和区间墙钟均值。孤立节点也可能来自未挂树的模型原型缓存，不能仅凭该数值判定泄漏。

## 尚不能据此下的结论

本轮没有做有渲染窗口的 GPU 分析，不能据此排除粒子透明叠加、绘制调用或显卡驱动造成的卡顿。也没有覆盖几十分钟、大规模军队和大量技能特效同时存在的情况；两分钟样本不足以证明不存在长期泄漏。

如果实际对战仍随时间恶化，下一步应在真实卡顿时段记录 `perf.summary()`、`perf.team_summary()` 和运行时长，结合 Godot Profiler / Visual Profiler 分离脚本时间、绘制时间与单位数量。优先核查动态寻路/目标搜索，再决定是否引入空间索引或异步路径预算。
