# 原创三族 Gameplay 框架：经济、属性、战斗公式与非对称机制

> 版本：0.4 · 日期：2026-09-14  
> 状态：原创对战规则框架提案。本文给出可进入灰盒验证的共同底盘和首轮参数种子；正式兵种、建筑、科技、数值与阵营名称仍需通过原型迭代。  
> 配套：[原创 RTS 设计总纲](ORIGINAL_RTS_VISION.md) · [当代史与三族官方战役](CONTEMPORARY_HISTORY_AND_CAMPAIGNS.md) · [战斗系统现状](COMBAT_SYSTEM.md) · [建造系统现状](BUILD_SYSTEM.md)。

> 三族首发兵种、数据种子、组合与反制详见 [三族首发单位设计](FACTION_UNIT_ROSTERS.md)。

## 1. 现阶段的设计顺序

世界观已经足以回答“为什么这些单位存在”。接下来按以下顺序设计，避免先堆单位名单再寻找规则：

1. 锁定共享经济、人口、单位属性和伤害结算。
2. 锁定三族各自的战略节奏、收益窗口和对手反制。
3. 为每族填写作战职责，不要求单位一一镜像。
4. 设计首发建筑、单位和英雄数据。
5. 用灰盒对局验证资源曲线、交战时长和机制可读性。
6. 数值稳定后再扩充第二英雄、完整科技和战役专属单位。

**非对称不等于三套互不相干的游戏。** 玩家换族时应继续理解采集、人口、移动、攻击和胜负目标；需要重新学习的是阵地怎样建立、部队怎样转线和优势怎样兑现。

## 2. 标准对局边界

| 项目 | 首轮目标 |
|---|---|
| 主要模式 | 1v1；后续再验证 2v2，战役规则不反向绑架对战 |
| 目标时长 | 15—25 分钟中位区间；不是强制时间上限 |
| 军队规模 | 常态约 15—28 个作战单位加一名英雄，视单位人口而变 |
| 人口上限 | 暂定100；三族首局起始上限均为15，人口设施的供给方式不同 |
| 科技阶段 | 完整目标三阶段；首个灰盒只开放第一阶段和少量第二阶段内容 |
| 英雄数量 | 每名玩家同时一名；首版每族一名可选英雄 |
| 胜利条件 | 摧毁对方所有“统治核心”建筑；原型允许认输，不先加入积分或奇观胜利 |
| 战争迷雾 | 保留；侦察到的阵营机制状态必须有可读表现，不提供全图情报 |

摧毁一座初始主城不能立刻越过所有后续据点判胜。只要玩家仍有能够生产工人和维持统治的核心建筑，就有重建机会；核心数量和升级规则在建筑表中锁定。

## 3. 资源体系

### 3.1 两种共享资源

| 资源 | 表现与来源 | 主要用途 | 设计作用 |
|---|---|---|---|
| **金币** | 金矿、贸易储备、税赋与任务奖励统一结算为金币 | 工人、军队、英雄复活、装备和多数科技 | 限制兵力规模与即时动员 |
| **材料** | 木材、石料、纤维和可用废料统一进入材料库存；地图首版主要从林木和材料堆采集 | 建筑、攻城器、阵营节点和高级科技 | 限制扩张、阵地与高级组合 |

“材料”是玩法库存，不宣称一捆木头可以物理变成石墙。各族在仓库中完成加工和调配，具体建筑仍通过模型、施工表现和说明显示真实材料。

魔力不是第三种玩家库存。施法者使用自己的法力，地图魔力节点改变地形或单位状态；首版不加入“魔晶矿”全局货币。阵营机制也不额外制造需要持续盯表的专属货币。

### 3.2 人口与地图资源不是货币

- **人口**是军队和经济规模上限，不会被交易或掉落。
- **英雄经验**只推动英雄单局成长，不用于购买科技。
- **法力**属于具体单位，不在玩家之间共享。
- **生境、补给区、已展开营地**是空间状态，不进入资源栏。
- 野外营地首先奖励金币、消耗品或地图信息，不随机掉落决定胜负的永久强装备。

### 3.3 资源分工

| 内容 | 金币倾向 | 材料倾向 |
|---|---|---|
| 工人、基础军队 | 高 | 无或低 |
| 建筑、居住空间 | 低或中 | 高 |
| 支援与高级军队 | 高 | 中 |
| 攻城器、阵营节点 | 中 | 高 |
| 英雄装备与复活 | 高 | 通常无 |
| 科技升级 | 高 | 中或高 |

金币不足迫使玩家减少即时兵力；材料不足迫使玩家延后基地、节点、人口和攻城能力。两种资源必须同时产生真实决策，不能让材料只在开局造两座房屋后失去价值。

### 3.4 首轮经济参数种子

以下只用于建立第一版灰盒，不是最终平衡承诺：

| 项目 | 初始值或范围 |
|---|---|
| 开局 | 600金币、250材料、5名工人、1座主城、15人口上限 |
| 工人 | 约60金币、1人口、20秒生产 |
| 基础战斗单位 | 90—140金币、0—30材料、2人口、20—28秒生产 |
| 专业单位 | 140—220金币、40—100材料、3—4人口、28—40秒生产 |
| 攻城单位 | 220—320金币、120—200材料、5—6人口、45—60秒生产 |
| 人口设施 | 约75—90材料；人类稳定供给，兽人随迁营变化，精灵受生境成熟影响 |
| 基础兵营 | 约180金币、120材料 |
| 第二阶段升级 | 约500金币、250材料，持续70—100秒 |
| 英雄 | 首名英雄不收取生产金币，受一次性召集时间约束；复活另行收费 |

首矿建议支撑一名玩家约十至十四分钟的常规采集，扩张矿储量略低于首矿。具体工人吞吐量在地图尺寸、行走距离和单位成本表完成后反推，不先照搬现成 RTS 的每趟数值。

### 3.5 取消、退款与资源安全

- 单位和科技在完成前取消，退还尚未消耗的全部成本；进度不得用于免费侦察或反复占队列。
- 已落地的建筑取消默认返还75%，阵营机制不能借打包、移栽或变形重置退款。
- 扣费、生成、取消和退款必须是一次事务；重复命令不得重复扣款或复制资源。
- 摧毁敌方建筑不会直接返还其完整造价。残骸回收若加入，收益必须远低于建造成本并有风险窗口。

## 4. 人口、科技与生产规则

### 4.1 人口

| 单位职责 | 建议人口范围 |
|---|---|
| 工人、轻型侦察 | 1 |
| 基础前排、基础远程 | 2—4，按阵营组织方式定价 |
| 支援、反重甲、强机动单位 | 2—5 |
| 攻城器、大型生物、精英单位 | 5—7 |
| 英雄 | 5 |

达到人口上限后不能开始新单位生产；已在队列中的单位可以完成，但在获得空间前停留于出口状态且不能参与战斗。失去人口建筑不会杀死现有单位，玩家进入人口超额状态，禁止继续训练直至恢复上限。

人口不是单纯表示人数，而是联盟维持一个作战单位所需的长期组织负担：人类计算粮秣、军饷与器材，兽人计算行军营位、牲畜和随队补给，精灵计算生境承载与盟约照料。三族使用同一个100上限，单位人口和人口设施规则不同。

| 联盟 | 人口结构 | 人口设施种子 | 100人口时的预期军队轮廓 |
|---|---|---|---|
| 人类 | **低—中消耗、连续分布。** 基础兵2人口，专员3—4，重型单位5—6 | 联排营舍约90材料，稳定提供10人口，不依赖补给连接继续存在 | 约16—20名工人、1名英雄和28—36个战斗实体；阵型密集、职责组合最完整 |
| 兽人 | **中—高消耗、单体较强。** 基础突击兵3人口，骑战与破阵4—6，攻城7 | 行军帐约75材料，展开提供10人口，打包途中保留5人口 | 约14—18名工人、1名英雄和20—28个战斗实体；单位少而结实，损失单体的代价更高 |
| 精灵 | **两极消耗。** 半身人侦察与轻支援1—2人口，精灵主力2—4，木灵和精锐6—7 | 栖庭约80材料，基础提供8人口；处于成熟生境时提供12人口 | 约16—20名工人、1名英雄和24—34个战斗实体；轻型网络成员较多，只能混入少量高负载生境单位 |

人口设施最终仍受100硬上限截断，不允许储存“备用人口”。兽人帐篷打包、精灵节点失去成熟都会造成可预见的人口超额；其惩罚只冻结新训练，不削弱现有军队属性，也不杀死或强制遣散单位。

这三种结构进一步改变对战风格：

- 人类通过较多中等单位维持宽正面和替补梯队，局部转向较慢，但单个单位阵亡不会立刻破坏整支部队的功能。
- 兽人用较少而强的单位集中突破，框选与路径更清楚；被集火击杀一个4—7人口单位时，战力和未来节奏会同时出现明显缺口。
- 精灵必须在轻型信息/支援成员与高人口木灵之间分配承载，能够铺开视野和区域，却不能同时堆满最坚固前排与最强攻城。

首版不采用低、中、高维护费或收入税。人口本身、扩张成本和地图资源负责限制大军，避免玩家必须记忆收入突然下降的隐藏阈值。

### 4.2 三阶段科技

| 阶段 | 主要内容 | 目的 |
|---|---|---|
| 第一阶段：立足 | 工人、基础前排、远程、侦察、基础防御和首名英雄 | 尽早产生侦察与小规模交战 |
| 第二阶段：结盟 | 支援、反重甲、阵营机制升级、商店和第一批攻城手段 | 形成兵种组合和英雄构筑 |
| 第三阶段：遗产 | 精英单位、完整攻城、终局科技和高风险战略能力 | 提供结束比赛的能力，不制造无法反制的全图效果 |

三族可以用不同建筑和仪式进入下一阶段，但升级成本与时间保持可比较。科技阶段是解锁边界，不直接给全军一次巨额属性跃迁。

### 4.3 生产与升级

- 一个生产建筑默认一条队列；切换兵种不损失已经完成的科技。
- 通用攻防升级首轮最多三级，每级提升控制在约8%有效战力以内。
- 同一级升级成本递增，不能同时对生命、伤害和护甲产生重复乘区。
- 阵营特色升级优先改变用途和窗口，例如补给区部署、营地展开或节点移栽，而不是单纯增加20%数值。
- 队列、成本、剩余时间和人口阻塞必须在 HUD 中明确显示。

## 5. 单位属性框架

### 5.1 所有单位的公共属性

| 属性 | 含义 | 规则 |
|---|---|---|
| 最大生命与当前生命 | 单位生存状态 | 当前生命降至0触发一次死亡流程 |
| 最大法力与当前法力 | 技能资源；无技能单位可以为0 | 法力恢复规则由单位和区域决定 |
| 护甲 | 抵抗物理伤害 | 使用递减收益公式，允许有限负值 |
| 魔法抗性 | 抵抗法术伤害 | 百分比，常规单位默认0%，特殊单位和英雄可拥有少量 |
| 移动速度 | 地面移动上限 | 减速和加速受全局上下限约束 |
| 碰撞半径 | 寻路、包围和近战接触 | 与视觉体型一致，不作为隐藏闪避属性 |
| 质量 | 抵抗击退和牵引 | 不改变普通伤害，不等于护甲 |
| 视野 | 战争迷雾揭示范围 | 昼夜系统未锁定前使用固定视野 |
| 人口 | 对军队规模的占用 | 与战术价值和生产时间共同定价 |
| 标签 | 生物、构装、英雄、建筑等规则身份 | 只供明确技能和目标规则查询 |

不设置力量、敏捷、智力三项通用主属性。英雄升级直接提高生命、法力、武器和护甲，装备也直接描述实际效果，避免“主属性同时影响多项数值”造成隐藏乘算。

### 5.2 武器属性

| 属性 | 含义 |
|---|---|
| 基础伤害 | 每次有效命中的确定性原始伤害 |
| 攻击周期 | 两次合法出手之间的最短时间 |
| 前摇 | 从开始攻击到伤害点或发射点的时间 |
| 后摇 | 伤害点后的表现时间；取消后摇不能提前下一次攻击 |
| 射程 | 从碰撞边界或统一测距点计算的攻击距离，方案实现时统一 |
| 弹道速度 | 远程逻辑弹道的移动速度；视觉弹道不决定命中 |
| 攻击类型 | 通用、穿射、破阵或攻城 |
| 目标规则 | 是否能攻击地面、空中、建筑或特定标签 |

普攻首版采用固定伤害，不使用伤害骰、隐藏未命中率或随机暴击。暴击、闪避和格挡只能由具有可见提示和明确冷却的技能提供。

## 6. 战斗公式

### 6.1 一次伤害的处理顺序

```text
目标与敌对关系合法性
  → 原始伤害
  → 攻击类型 × 防御类别倍率
  → 护甲或魔法抗性
  → 护盾与临时减伤
  → 当前生命
  → 死亡与事件结算
```

所有普攻、技能、持续区域和物品伤害进入同一伤害管线。视觉弹道、动画和飘字只消费结算结果，不拥有扣血权。

### 6.2 防御类别与物理攻击倍率

单位只有一个主要防御类别；英雄同时带英雄标签，但仍使用下表的英雄列。首轮倍率控制在0.35—1.60之间，避免看见目标却几乎打不动。

| 攻击类型 | 轻装 | 重装 | 英雄 | 建筑 |
|---|---:|---:|---:|---:|
| 通用 | 1.00 | 1.00 | 1.00 | 0.50 |
| 穿射 | 1.25 | 0.75 | 0.90 | 0.35 |
| 破阵 | 0.80 | 1.25 | 1.00 | 0.80 |
| 攻城 | 0.60 | 0.90 | 0.50 | 1.60 |

- **通用**用于基础近战和没有明显专长的武器。
- **穿射**克制轻装远程、施法者和侦察单位，对重甲与建筑较弱。
- **破阵**用于重锤、长柄重击和专门反重甲单位，对轻装效率较低。
- **攻城**负责结束基地，不应成为清理普通部队的最佳选择。

法术伤害不使用这张物理倍率表，直接进入魔法抗性；个别技能可以声明对建筑或特定标签的独立倍率。

### 6.3 护甲公式

物理伤害在攻击类型倍率之后计算护甲。令 `A` 为最终护甲：

```text
当 A >= 0：护甲倍率 = 20 / (20 + A)
当 A <  0：护甲倍率 = 2 - 20 / (20 - A)

最终物理伤害 = 原始伤害 × 攻防倍率 × 护甲倍率 × 其他明确修正
```

示例：30点通用伤害攻击5点护甲的重装单位：

```text
30 × 1.00 × 20 / 25 = 24点伤害
```

30点穿射伤害攻击同一目标：

```text
30 × 0.75 × 20 / 25 = 18点伤害
```

护甲首轮限制在 `-10` 至 `40`。内部以浮点数结算，HUD 四舍五入显示；合法普攻在没有免疫规则时至少造成1点伤害。

### 6.4 魔法伤害与治疗

```text
最终魔法伤害 = 原始魔法伤害 × (1 - 魔法抗性) × 其他明确修正
实际治疗 = 原始治疗 × 治疗承受倍率
```

- 魔法抗性常规范围为0%—40%，硬上限60%，负魔抗首版不开放。
- 治疗不受护甲影响，不能超过最大生命。
- 同类治疗削减只取最强效果，首轮下限为50%治疗承受。
- “真实伤害”首版不作为常规单位能力；必须绕过防御的剧情机制单独声明。
- 建筑受到的法术伤害默认乘0.40，除非技能明确具有攻城职责。

### 6.5 护盾、减伤与吸收顺序

1. 类型倍率与护甲/魔抗先确定伤害。
2. 百分比减伤只取同组最强值，不让多个区域无限相乘。
3. 固定护盾吸收剩余伤害；多个护盾按最早获得者先消耗。
4. 未吸收部分扣除生命。

普通百分比减伤硬上限50%。无敌属于独立状态，必须非常短、明显可见且不能由通用装备提供。

## 7. 攻击节奏、移动与控制

### 7.1 攻击时序

- 前摇完成前移动或改令会取消本次攻击，不产生伤害。
- 伤害点之后可以移动取消后摇，但攻击周期继续计算，不能借操作提高理论攻速。
- 远程弹道由逻辑层追踪命中、丢失或超时；表现弹道不能决定扣血。
- 默认攻击不追踪进入战争迷雾且失去合法信息的目标；弹道已经发射后的处理由弹道类型明确。

### 7.2 移动速度修正

```text
最终速度 = 基础速度 × (1 + 最强加速 - 最强减速)
```

- 常规加速上限30%，减速上限40%。
- 同类加速或减速只取最强，不相加；特殊大招若突破上限必须在技能中写明。
- 路径、碰撞和地形造成的实际绕行不算减速效果。
- 高地首版只提供视野和通行优势，不加入随机未命中率。

### 7.3 硬控制递减

眩晕、恐惧、沉默式完全失控进入同一“决心”窗口：

| 同一单位8秒内受到次数 | 持续时间 |
|---|---:|
| 第一次 | 100% |
| 第二次 | 50% |
| 第三次及以后 | 0%，只显示免疫反馈 |

英雄额外把基础硬控时长乘0.60。减速、位移和区域封锁不进入硬控递减，但分别受速度上下限、质量和可通行规则约束。首个灰盒以减速和短位移为主，暂不批量加入眩晕。

## 8. 英雄规则

- 每族首发一名英雄，同时只控制一名。
- 最高10级；1级拥有两个基础主动技能与一个固有特性，5级解锁终极技能，3/6/9级进行天赋二选一。
- 经验由范围内参战英雄共享，不要求最后一击；高等级英雄反复清理低级营地收益递减。
- 英雄没有力量/敏捷/智力主属性，等级成长直接写入生命、法力、护甲和武器数据。
- 武器、护具、遗物各一槽；背包六格。只有装备栏物品提供装备属性。
- 英雄对攻城、守多线和持续承伤都有明确缺口，基础军队在英雄阵亡后仍可行动。

首轮复活参数种子：

```text
复活时间（秒） = 12 + 3 × 英雄等级
复活金币 = 100 + 25 × 英雄等级
```

复活保留等级、天赋和装备，不重置装备或技能原有冷却。战役可以使用剧情复活点，对战必须遵守统一公式。

## 9. 参考原则：共享语言，非对称答案

本作从两类经典 RTS 中抽取设计方法，不复制其阵营外形、单位组合或专属机制：

- 《星际争霸Ⅱ》的三族共享矿物、高能瓦斯和人口等基本概念，但工人如何施工、建筑如何成立、生产能力如何展开存在根本差异；官方回顾也把“让各族真正以不同方式游玩”列为设计目标。对本作的启示是：**阵营差异必须从第一名工人、第一座兵营和第一次转线就能感受到，而不是只在终局单位或被动加成里出现。**参考：[资源与建造说明](https://news.blizzard.com/en-us/article/4488900/game-guide-resources) · [建筑说明](https://news.blizzard.com/en-us/article/4488317/game-guide-buildings) · [Beta 回顾](https://news.blizzard.com/en-us/article/39345/starcraft-ii-beta-retrospective)。
- 《帝国时代Ⅱ》让文明共享兵种类别、资源、时代和克制关系，再通过科技树开放范围与文明专长改变发展路径。对本作的启示是：**玩家换族后应继续读得懂经济、阶段、护甲与反制，只需学习这个联盟如何组织同一套战争。**参考：[官方文明与游戏模式入门](https://www.ageofempires.com/learn-to-play/civilizations-game-modes-aoe2/)。

因此，本作采用“《帝国时代》式共享识读＋《星际争霸》式战略身份”：两种资源、人口、科技阶段、攻击类型和必要作战职责共享；施工、生产展开、领土经营、转线方式与优势兑现不同。三族必须都有反轻装、反重甲、侦察、续航和攻城答案，但答案不要求由相同数量、造价曲线或操作方式的单位承担。

### 9.1 一句话必须能约束玩法

一句话定位不是宣传语，而是内容筛选器。它必须连续回答五件事：

1. 玩家如何投资地图；
2. 玩家怎样获得主动权；
3. 一场战斗中反复执行什么动作；
4. 优势怎样被对手看见和拆除；
5. 玩家在什么情况下会输。

本文中的**战略**指未来约1—3分钟的资源、科技、扩张和战线选择；**战术**指约1—15秒内的阵型、集火、位移、技能和撤退。每个阵营机制必须同时影响两层，并通过建筑状态、地面范围、打包动作或成熟进度向对手提供信息。

### 9.2 三族总览

| 联盟 | 一句话描述 | 战略动词 | 核心优势 | 核心弱点 | 对手首先观察什么 |
|---|---|---|---|---|---|
| 人类联盟 | **把战线建成家园：用可连接、可修复的补给网络换取最可靠的正面推进。** | 连接 | 稳定生产、混编协同、成熟战线 | 固定资产昂贵，转线慢 | 仓站连接与新据点施工 |
| 兽人联盟 | **把家园带上道路：以迁营和主动开战选择战场，在敌人完成部署前集中优势。** | 迁移 | 调动、先手、局部兵力集中 | 迁营会停产并暴露经济，持久攻坚弱 | 营车去向与展开窗口 |
| 精灵联盟 | **让战场成为盟友：以会成熟、可被破坏的生境网络塑造地形和长期交换。** | 培育 | 区域控制、信息、连续作战 | 新战场启动慢，多线骤变困难 | 节点年龄、连接与信标 |

三族都围绕地图空间建立优势，但决策问题不同：人类问“补给线接到哪里”，兽人问“何时把产能搬到哪里”，精灵问“下一场战斗要提前在哪里成熟”。

## 10. 三族非对称机制

三族差异集中在**空间组织方式**：人类建立补给网络，兽人移动生产能力，精灵培育生境网络。三者都能离开优势区域战斗，但长期作战方式不同。

### 10.1 人类联盟：补给网络与协同施工

**一句话：把战线建成家园：用可连接、可修复的补给网络换取最可靠的正面推进。**

**战略特点**

- 以主城—仓站—前线据点构成逐段投资的扩张路线；每向前一步都提高补员与维修效率，也增加必须守护的固定资产。
- 经济和生产节奏最平稳，适合先侦察敌军构成，再用混编部队和对应科技逐步推进。
- 能通过多名工人加速关键建筑，把材料换成抢占阵地的时间；加速越多，边际效率越低。
- 换战区前通常要先建新连接，因此擅长把一次局部胜利转化为堡垒、扩张和攻城阵地，不擅长突然跨越地图救火。

**战术特点**

- 依靠楔盾前排、部署远程、工程维修和英雄保护形成可预测但牢靠的阵型。
- 常用动作是交替掩护、短距离前推、受损单位回撤整备，再由攻城器迫使敌人接战。
- 可以在准备充分的正面承受冲击；侧翼被绕过、仓站被切断或部队被引离整备区后，交换效率明显下降。

**优势**

- 三族中生产最稳定、正面容错最高，单位职责清晰，新玩家容易把经济转化为战斗力。
- 成熟补给线内的维修、换装与连续增援可靠，赢下一场正面战斗后最容易稳步占地。
- 混编部队应对面广，防御转进攻的路径清楚。

**弱点与失败方式**

- 仓站、道路关系和重型设施占用大量材料；同时经营两个方向会稀释主力和施工速度。
- 远距离转线最慢，机动部队被孤立时缺乏持续恢复；遭遇多线佯攻容易把钱花在错误方向。
- 最典型的失败不是正面瞬间崩溃，而是外部经济被袭、连接连续中断，庞大军队因补员迟缓而失去地图。

- 主城、仓站和前线据点形成有限范围的**整备区**。
- 单位脱战后在整备区恢复速度提高，机械和建筑维修更有效；装备更换也依赖有效整备区。
- 仓站必须与主城或另一座有效仓站保持可读连接；连接被切断后保留短暂储备时间，随后失去整备收益。
- 多名工人可以协同建造或维修同一建筑，但额外工人效率递减并产生附加材料消耗。
- 人类生产稳定、堡垒和远程协同可靠，但离开网络后恢复慢，远距离转线成本最高。

**对手反制：** 袭击仓站、切断连接、迫使人类在两个方向建立昂贵网络，或在其新据点尚未完成时交战。

首轮机制只验证“主城/仓站整备区＋可摧毁连接＋多工施工”，不立即实现复杂道路寻路或运输车模拟。

### 10.2 兽人联盟：迁营与展开窗口

**一句话：把家园带上道路：以迁营和主动开战选择战场，在敌人完成部署前集中优势。**

**战略特点**

- 将部分产能、人口和交付能力搬到新的资源区或进攻方向，用移动时间换取更短的增援距离。
- 通过侦察、佯动和营地位置持续制造多个威胁，迫使对手先暴露防守投入，再集中主力攻击薄弱处。
- 第一、第二阶段更容易取得节奏主动；进入长期攻城前必须把机动优势转化为扩张、断供或兵力差。
- 搬迁会中止对应设施的生产与功能，所以“移动多少、留下多少”是核心经济决策，不能无成本全家搬走。

**战术特点**

- 依靠狼盟侦察、短距突进、破绽标记和定向行军形成先接触、集中击杀、脱离后再进场的循环。
- 擅长从宽阔地形和多条道路同时出现，击杀落单支援与攻城器；在狭窄入口持续顶住重甲阵线的效率较低。
- 展开营地可以就近补员，但打包、运输和落地都形成敌人可识别的进攻窗口。

**优势**

- 三族中转线最快，最容易获得局部人数优势，并把敌人的错误部署放大成资源损失。
- 扩张方向灵活，失去一块固定领土后仍可能通过换线保住产能。
- 侦察与先手能力强，适合主动型玩家用路线、时机和佯攻表达水平。

**弱点与失败方式**

- 营车同时承载经济与生产价值，被截获时可能一次损失建筑、人口和未来增援。
- 正面持续攻坚、固定防御与长时间对射不占优势；若无法制造侧击，就会被准备充分的阵地消耗。
- 最典型的失败是迁营路线被读懂、数座设施同时停产或被截，前线军队看似主动却得不到下一轮兵力。

- 部分生产、人口和支援建筑可以**打包为营车**并重新部署；主城和少数重型设施不能随意移动。
- 打包期间停止生产、科技和恢复效果；人口设施在途中只保留一半供给。营车移动较慢、无法攻击且被摧毁会损失建筑。
- 展开的营地提供火塘整备、资源交付和单位补充，但强度依赖实际建筑，不产生免费全军增益。
- 工人可以向最近已展开营地交付资源，使兽人能改变采集方向；营地移动时必须重新规划运输。
- 灰途盟作为第二层机制，在侦察、护运和少量骑乘突击中选择伙伴职责，不形成额外资源条。

**对手反制：** 侦察迁营路线、在打包或展开窗口突击、封锁狭窄通道，或逼迫兽人在保护经济和支援前线之间选择。

首轮只允许兵营和仓帐迁移，限制同时处于打包状态的建筑数量，避免整座基地无风险逃跑。

### 10.3 精灵联盟：生境网络与远枝信标

**一句话：让战场成为盟友：以会成熟、可被破坏的生境网络塑造地形和长期交换。**

**战略特点**

- 提前判断下一处资源争夺、路口或攻城方向，在交战前投资节点、信标和连接，而不是临战瞬间获得完整主场。
- 通过视野、路径限制和脱战恢复建立层层相接的区域；成熟网络越大，维护点越多，也越容易被多线牵扯。
- 可以放弃或移栽局部节点来重新塑造战线，但重新成熟期间会出现清晰空窗。
- 半身人信标扩展信息而不直接增加伤害，使精灵更容易选择有利交换，却仍需军队亲自守住节点。

**战术特点**

- 依靠延迟区域、拉扯、局部恢复和路径塑造反复交换，目标是让敌军在进入、退出和再次接近时持续付费。
- 擅长在成熟生境中保护远程与支援，控制狭窄通路；离开网络抢救远端目标时，瞬时正面能力较普通。
- 技能效果应有地面预警和可拆来源，精灵玩家通过预判赢得位置，而不是用不可见控制锁死敌人。

**优势**

- 成熟区域内拥有最强的信息密度、空间控制和连续作战效率，尤其擅长防守资源点与拆解正面冲锋。
- 通过节点几何和信标视野提前发现攻势，能以较少伤亡赢得多轮交换。
- 当战线稳定时，军队与地图机制的组合深度最高。

**弱点与失败方式**

- 节点幼体、孤立连接和信标都脆弱；突然出现在陌生区域时无法立刻复制成熟主场的效率。
- 同时保护多个新区域困难，节点投资方向错误会造成材料和时间沉没。
- 最典型的失败是被迫连续救火，旧网络被绕开、新网络未成熟，军队在一次次仓促接战中失去交换优势。

- 育土者能够建造数量受限的**生境节点**，节点形成可见区域并连接附近精灵建筑。
- 节点区域提高脱战恢复和特定技能效率，允许部分建筑获得完整功能；军队在区域外仍保留基础战斗能力。
- 节点需要成熟时间且可以被攻击、净化或切断；成熟区域强，但无法瞬间铺到新战场。
- 弥珞等能力可以移栽一个节点，移栽有距离、冷却和重新成熟窗口。
- 半身人远枝信标提供侦察、测绘和节点间信息连接，不直接复制精灵自然建筑；信标暴露后容易被远程破坏。

**对手反制：** 在节点成熟前进攻、同时威胁多个区域、优先摧毁信标和孤立节点，或绕开已经经营成熟的正面。

首轮机制只验证“三个节点上限＋成熟时间＋局部恢复/技能交互＋可摧毁”，不加入全图传送或资源自动再生。

### 10.4 强势期、操作表达与非固定克制

| 维度 | 人类 | 兽人 | 精灵 |
|---|---|---|---|
| 第一阶段 | 稳定立足，防守反击可靠 | 最能主动探路和施压 | 投资首批节点，避免过早多线 |
| 第二阶段 | 混编与前线仓站成形，稳定强势 | 迁营与机动力完整，主要兑现期 | 生境连成局部网络，开始控制战区 |
| 第三阶段 | 攻城与补给推进可靠，但转向昂贵 | 仍能切线，拖入纯正面消耗则效率下降 | 成熟网络最强，但被拆节点仍会失去收益 |
| 主要水平表达 | 路线规划、阵型、维修与分批增援 | 读图、佯攻、切入时机与撤退保存 | 预判、节点几何、区域技能与控制撤退 |
| 失误代价集中处 | 错建固定资产 | 营车被截和停产时机 | 节点投错位置或未成熟即接战 |

强势期是决策窗口，不是计时器决定的胜负。兽人到第三阶段仍有结束比赛的手段，精灵在第一阶段也必须能抵抗进攻，人类也不能靠成熟阵地自动取胜。

三组对局形成可理解的张力，但不组成固定石头剪刀布：

- **人类对兽人：** 人类在准备好的正面占优；兽人可以同时威胁仓站、扩张和施工队，切断连接后再集中。
- **兽人对精灵：** 兽人能赶在节点成熟前换线；精灵若守住信标和通路，会让反复冲锋在生境中不断亏损。
- **精灵对人类：** 精灵能改变路线、延缓笨重推进；人类可用稳定攻城逐段拆除网络，并把清出的土地接入补给。

每族首个完整版本至少提供两种可行开局和两种主力组合。阵营专长应引导决策，不能把玩家锁进唯一正确流程。

### 10.5 非对称预算表

| 维度 | 人类 | 兽人 | 精灵 |
|---|---|---|---|
| 建立优势速度 | 中 | 快，但有展开风险 | 慢，需要成熟 |
| 转移阵地 | 慢 | 最快 | 中，受移栽冷却限制 |
| 固守成熟阵地 | 强 | 中 | 最强 |
| 生产稳定性 | 最强 | 迁营时中断 | 依赖节点和区域 |
| 脱战恢复 | 补给网络内稳定 | 已展开营地附近灵活 | 成熟生境内强 |
| 主要暴露窗口 | 新仓站和连接未完成 | 打包、运输和展开 | 节点幼体与移栽后 |
| 对手主要目标 | 仓站和网络连接 | 营车和展开点 | 节点与远枝信标 |

任何一族的机制都不能直接获得无条件金币或材料倍率。空间优势需要投资、可被侦察、能够被破坏，并在失去设施后停止提供收益。

## 11. 兵种与建筑的框架槽位

### 11.1 作战职责，不做逐项镜像

每族必须覆盖以下能力，但可以由不同数量和组合的单位承担：

| 必需能力 | 设计要求 |
|---|---|
| 工人和建设 | 能采集、建造、维修或恢复阵营设施 |
| 稳定前排 | 能保护远程和争夺狭窄区域，不能同时拥有顶级机动 |
| 持续远程 | 能逼迫纯近战接近，对贴身和侧击有弱点 |
| 侦察与反侦察 | 提供信息优势，不依靠永久全图隐形 |
| 反重甲 | 能处理高护甲目标，对轻装或建筑效率较低 |
| 支援与续航 | 提供恢复、保护、驱散或机动中的有限组合 |
| 攻城 | 能有效结束建筑，对普通军队效率受限 |
| 英雄协同 | 至少两种单位能明显利用首发英雄创造的窗口 |

不要求每族恰好七种单位。人类可能用独立攻城器完成攻城；兽人大型单位可以兼顾破阵和有限攻城；精灵可能让一个需要节点准备的单位切换职责。多职能单位必须在同一时间只能发挥一项主要作用。

### 11.2 建筑职责

| 建筑槽位 | 必需功能 |
|---|---|
| 统治核心 | 工人生产、科技阶段、胜负条件和基础资源交付 |
| 人口建筑 | 提供人口上限，并与阵营机制产生有限联系 |
| 基础兵营 | 生产第一阶段核心军队 |
| 专业设施 | 生产支援、反重甲或阵营盟友单位 |
| 攻城/高级设施 | 提供攻城与第三阶段内容 |
| 经济交付点 | 缩短材料或金币运输，承担可袭击的经济节点 |
| 防御建筑 | 保护关键位置，单独堆叠不能击败同成本攻城军队 |
| 英雄设施 | 首次召集、复活和英雄信息入口 |
| 商店/工坊 | 装备、消耗品和有限战术工具 |
| 阵营节点 | 仓站、可迁营建筑或生境节点；可以与上述建筑重合 |

建筑总数首轮控制在每族7—9座。一个建筑可以承担两个槽位，避免为了形式完整制作三套庞大菜单。

## 12. 战斗节奏与平衡目标

### 12.1 时间到击杀

首轮采用以下体验目标，而不是先追求单位属性看起来宏大：

- 等人口基础单位单挑通常需要6—10次有效普攻分出胜负。
- 同科技、同人口的正面小队交战应给玩家至少3—6秒识别并下达一次有效命令。
- 英雄被同人口军队集火时不能瞬间死亡，缺少撤退和保护时也不能坚持超过约15—22秒。
- 攻城单位在没有护卫时应被普通军队快速处理；受到完整保护时能够在合理时间内摧毁防御建筑。
- 恢复能力延长连续作战，不应在交火中抵消同人口敌军的主要伤害。

### 12.2 平衡比较单位

每次评审至少同时比较：

1. 相同金币与材料成本。
2. 相同人口。
3. 相同生产建筑数量和生产时间。
4. 相同科技阶段。
5. 有无阵营空间机制支持。
6. 玩家需要的操作次数与失败代价。

只比较一对一单挑会错误估价支援、机动、射程和建造速度；只比较满编决战又会忽略开局窗口和转线能力。

### 12.3 硬性边界

- 常规克制倍率不超过1.60，不低于0.35。
- 普通减伤不超过50%，魔抗不超过60%。
- 常规加速不超过30%，减速不超过40%。
- 连续硬控触发决心递减。
- 同类光环和区域效果默认只取最强，不无限叠加。
- 没有免费全图传送、永久控制敌军、无限尸体收益或不可摧毁阵营节点。
- 装备不能补齐某族最核心的结构弱点，例如让兽人获得最强固定堡垒或让人类无风险迁移整座基地。

## 13. 灰盒验证顺序

### G0：共享底盘

- 只用一种测试阵营验证金币、材料、人口、生产、攻击类型、护甲公式、英雄复活与胜负。
- 使用固定伤害和固定地图，不加入随机营地装备。
- 验收同一输入能重复得到相同战斗结果。

### G1：三种空间机制

- 每族只接入工人、前排、远程、英雄和主基地。
- 人类启用一个仓站连接；兽人允许一座兵营迁营；精灵允许三个生境节点。
- 使用相同单位基础模板，先测机制本身值多少成本，再加入兵种个性。

### G2：职责组合

- 加入侦察、支援、反重甲和攻城能力。
- 验证三族都能处理轻装海、重甲推进、阵地龟缩和多线骚扰。
- 记录机制启动时间、首次交战、首次扩张、单位损失与胜负转化。

### G3：英雄构筑

- 开启装备、天赋、完整技能和复活成本。
- 逐项检查装备是否抹平阵营弱点，天赋是否存在唯一最优路径。
- 战役专属规则与多人对战数据分离。
