# HUD 布局重设计：信息完整、英雄操作与全局队列

日期：2026-09-23。状态：设计提案，未修改运行 UI。

控件抽象与组合结构见 [HUD_WIDGET_CATALOG.md](HUD_WIDGET_CATALOG.md)。

配套：[模块边界](../../architecture/GAMEPLAY_MODULE_BOUNDARIES.md)、[Gameplay 重构策划](../../architecture/GAMEPLAY_REFACTOR_PLAN.md)。本文的“现有界面”指当前项目 HUD，不指 Warcraft III 或《帝国时代 IV》的完整界面。

## 1. 方向

保留 RTS 的左小地图、中选择详情、右命令面板习惯，建立统一布局容器。采用较扁平、低装饰、明确交互状态的视觉；英雄有专属信息区，但不另建一套命令机制。增加可定位的全局生产/研究总览和控制组栏。

优先修复内容溢出、信息命名、布局冲突与快捷键冲突，再换主题。原代码已使用 StyleBoxFlat，目标不是简单“去掉纹理”，而是让信息完整、位置稳定、操作反馈一致。

## 2. 当前检查结果

证据来自当前 `game/scenes/game_hud.tscn`、`game/scripts/presentation/game_hud.gd` 及相关模块的静态检查；未对当前游戏逐状态截屏，因此不把潜在遮挡描述为已复现的所有分辨率问题。后续 UI 实现必须做实际矩形与截图检查。

| 问题/现状 | 代码证据 | 判断与处理 |
|---|---|---|
| 三块底部区域分别定位 | 小地图宽 192；中央 offset ±240；右侧宽 240，分别锚定 | 缺少共同宽度预算。按初始偏移计算，宽度低于 976 时中央与右侧存在交叠；实际还受容器最小尺寸影响。改共同 HBox/Grid 容器和紧凑布局。 |
| 多选条超出中央预算 | `_refresh_multi_strip` 最多 16 个、每个最小宽 36，单行 HBox | 仅图标就需 576，超过中央名义 480，尚未计间隔与边距。不能靠“第 17 个变 +N”解决；改按类型聚合、分页/滚动详情。 |
| 中央面板内容种类太多 | 肖像、属性、多选、施工、生产队列、Buff 纵向组合，面板初始高 160 | 不同模式最小高度差异大，有扩张/侵占世界风险。用明确的单位/英雄/建筑/多选布局模板替换任意叠加。 |
| 背包成为独立悬浮块 | `_layout_inventory_panel` 把 144×260 面板放到命令区上方 | 占用右侧较高世界区域，未参与统一布局。英雄背包移到底栏固定槽区，紧凑模式切到英雄详情页。 |
| 底栏缩放不统一 | `_apply_bottom_height` 只按视口高度调整右命令区，其他区使用固定偏移 | 字号、图标、区域高度不同步。统一 Theme 尺度和容器最小尺寸，不仅修改一个 offset。 |
| 开发提示锚点不一致 | HintLabel 默认顶端锚点，运行时却写入按底栏计算的负 offset；DebugStatusLabel 是底端锚点 | 从代码可推导提示可能落到视口上方。开发叠层独立布局，游戏操作说明不要依赖开发提示。 |
| 研究并非没有显示 | ProductionPanel 已构建研究槽；ProductionModule.collect_owner_activities 包含 research/upgrade；Director 接入 ActivityFeed | 延续现有数据基础，不能重新实现第二套研究队列。 |
| 研究与训练语义混杂 | `set_train_queue` 固定标题“训练” | 改为“生产队列”，每项标注训练/研究/升级/复活；纯研究页可用“研究”。 |
| 全局活动仅有当前项 | collect_owner_activities 取每建筑 snapshot[0]；building_id 为 typeId | 缺少等待总览、唯一来源建筑定位、稳定任务 ID，无法可靠操作同类型多建筑任务。 |
| 全局条缺少空间上限 | ActivityFeed 固定区间内使用 VBox，按全部 entries 建行 | 大量建筑时存在向底栏扩张/覆盖风险；设置可见行数、滚动/展开和 +N，不静默隐藏任务。 |
| 英雄已有部分特化 | 经验条、等级、背包已存在 | 继续完善常驻英雄入口、技能点、死亡/复活状态，不宣称从零支持英雄。 |
| 未发现控制组栏 | 当前 HUD 场景和本地交互代码检索没有明确控制组栏实现 | 多选头像条不能替代持久控制组；单独设计状态与视图。 |
| 热键与镜头有冲突风险 | CommandCardModule 按 key→action 写表；相机 `_get_pan_input` 轮询 WASD | 重复键可能被后写覆盖；UI 消费事件也无法自动阻止轮询镜头。重组按键必须同时处理相机与焦点。 |

旧 `HUD.md` 的“生产队列未接”已落后于当前代码；本次补充文档明确这一差异，不按旧状态重新规划。

## 3. 推荐布局

下面是信息分区示意，不是已运行截图，方框不代表必须用厚边框。

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 英雄快捷栏                 对局时间        金 / 木 / 人口       菜单     │
│ H1 血蓝 等级                                                        │
│ H2 血蓝 死亡/复活      游戏世界：保留中央视野                         │
│                                                                         │
│ 全局生产/研究                                                通知区     │
│ [研究] 图标 等级 进度 剩余      不占用中央瞄准区域             最多数条   │
│ [训练] 图标 ×N 来源 +等待                                                │
├──────────┬──────────────── 控制组 1…0 ──────────────────────────────────┤
│          │ 选择详情             │ 英雄扩展 / 建筑队列 │ 上下文命令      │
│ 小地图   │ 肖像、血蓝、关键属性  │ 物品六格 / 生产进度 │ 固定 4×3 网格   │
│          │ 多选时改类型摘要     │ 随选择模式切换      │ 禁用原因/快捷键 │
└──────────┴──────────────────────┴───────────────────┴──────────────────┘
```

信息位置分三类：

- 常驻：经济、时间、小地图、已有英雄入口、非空控制组。
- 上下文：选择详情、技能/建造命令、背包、所选建筑队列。
- 按需：完整属性、科技树、长 Buff 列表、完整生产总览、Tooltip。

不让所有信息同时展开，也不让关键进度只能藏在 Tooltip。宽屏无需填满整个底边；保持小地图与命令区可达，中央区有最大宽度。

### 初始尺寸预算（设计逻辑像素，待实机校准）

参考 1920×1080、UI 100%：外边距 16、间隔 12；底部主体约 224 高，控制组约 32 高；小地图 224、选择详情 360、上下文扩展 240、命令区 256。总宽预算 1148，可在较窄窗口保持最小可操作布局。按钮不低于约 44×44，常规文字约 14–16。

宽度以“视口宽 / UI 缩放”判断，而非仅看物理分辨率：

- 可用宽 ≥1440：完整详情，英雄背包 3×2，生产队列就地显示。
- 1100–1439：小地图约 192，选择详情约 300，扩展区约 220，命令区约 224；减少装饰和次要属性。
- <1100：扩展内容成为详情区中的有标签页；血蓝、当前任务、命令和小地图继续可见，英雄物品页提供明确切换与独立热键。需要时增加底栏高度，禁止横向互相覆盖。

这些阈值是起始设计值；必须按控件实际 minimum size 校准。16:9、16:10、21:9 与 UI 125%/150% 都需要验证，不以缩小字体直到放下为策略。

## 4. 英雄 UI：特殊化信息，复用操作规则

**应特殊化。** 英雄具有经验、等级、技能点、物品和复活等普通单位没有的持续关注需求。

- 常驻英雄快捷栏：自有英雄肖像、等级、血/蓝、可用技能点、死亡/复活进度。单击选择，双击定位；不展示所有 Buff 或长技能描述。
- 选中英雄：名称/等级、血蓝、经验、关键属性、Buff 摘要、物品六格；技能仍位于统一命令区，槽位稳定。
- 技能升级：技能点角标常驻可见；升级模式使用明确标签和“返回”，不能靠把施法按钮突然换成升级按钮而不提示模式。
- 混编：英雄可作为摘要中的独立项，显示当前主选；切换英雄不能暗中清空整个选择集合。具体单选与主选切换采用不同输入动作。
- 死亡：保留英雄条位置，显示死亡或复活状态，不让其消失导致快捷入口重排。
- 敌方英雄：只显示规则允许、当前可见的信息；不暴露隐藏背包、冷却或不可见时持续更新的血量。

背包 3×2 是目标视觉排列，原索引/存档语义保持不变，通过显示映射处理；物品槽位热键与 1…0 控制组分离。普通单位也可按能力展示背包，不把所有 UI 条件写成 typeId 白名单。

## 5. 全局生产与研究：借鉴 AoE IV 的可见性

官方 Season One 更新说明确认 AoE IV 提供 Global Build Queue，并可设为 Upgrades Only，也扩展了全局快捷键。这里借鉴“跨建筑观察生产/升级”的信息原则，不声称复制其完整当前布局或交互。[官方说明](https://www.ageofempires.com/news/age-of-empires-iv-season-one-update-release-notes/)

建议全局面板具备“全部 / 研究与升级 / 训练”筛选，默认优先展示研究/升级，保留其他活动计数。显示图标、名称、目标等级、当前进度、预计剩余时间、来源建筑和等待数量。紧凑模式最多约 4 行并显示 +N；展开面板能访问全部任务，不能只截断数组。

当前项目每建筑可能共用训练与研究队列，UI 分类不能擅自改成可并行执行的两条玩法队列。等待项显示“等待”，不画一个正在推进的假进度。暂停/受阻要有原因；没有可信 ETA 时不要显示精确倒计时。

交互：单击任务选择来源建筑，双击定位；取消通过详情中的显式按钮，经生产命令入口处理，不能把浏览默认设为取消。退款显示读取规则结果，不在 UI 硬编码“全额退款”。多个同类任务可聚合，但必须能展开到确切建筑和订单。

展示契约建议：task_id、source_entity_id、owner_id、kind、definition_id、target_level、status、progress、remaining/ETA、queue_position、waiting_count、可取消状态/原因。当前 building_id=typeId 仅是类型信息，不够作为任务定位身份。

## 6. 快捷键和按钮可以重组，但必须成套设计

建议提供两种预设：经典语义键，以及固定位置网格键。网格模式采用 4×3 的 QWER / ASDF / ZXCV；需关闭 WASD 镜头移动，改用边缘滚动、中键拖动或方向键。经典模式如启用 WASD，也必须检测 A/S 等语义命令冲突，不能默认认为安全。

- 基础命令固定位置，单位技能、建筑生产/研究按稳定分类占位；解锁新技能不挪动已有按钮。
- 超过 12 项使用有名称的分类页，例如“基础 / 建造 / 科技”；显示当前页和返回键，不无提示自动换页。
- 控制组保留数字行；物品另设独立键区；英雄选择键可配置，不直接占用现有 F3 性能、F4 GM 等开发键。开发快捷键仅在开发上下文注册。
- BindingProfile 分开保存 action_id→绑定 与 card_slot→绑定；最终解析为同一意图。提示文字必须来自解析后的绑定，不能另写一份静态字母。
- 同一活动上下文内重复绑定报冲突，不采用字典后写覆盖。禁用按钮仍能解释“资源不足”等原因；热键不会落入别的同键动作。
- 输入优先级：模态窗口/重绑捕获→文本编辑→目标选择模式→上下文命令→全局选择/镜头。Shift 队列、Ctrl 控制组等修饰键单独定义。
- 相机轮询也必须服从焦点和输入上下文；仅 set_input_as_handled 不足以阻止 Input.is_key_pressed。
- 重绑支持恢复默认、冲突提示、持久化；首次重构不静默覆盖用户已保存的配置。

## 7. 控制组应该显示；队形是另一件事

底栏上缘显示非空控制组：数字、代表图标、单位数、当前选择状态。受攻击提示使用角标/短暂闪烁，不依赖红绿颜色。编辑控制组时可显示全部 1…0 槽位。

建议 Ctrl+数字覆盖创建、Shift+数字追加、数字召回、双击数字定位；所有绑定可配置。成员死亡更新数量，不因一名成员死亡删除整组；全组为空显示短暂空态后按规则处理。控制组属于本地玩家交互状态，不是对战 AI 的军队对象。

“队形”另放在多选单位上下文中：自由、横队、纵队等，仅在玩法实际支持时出现。没有编队执行器时不要放能点击但没有效果的按钮。控制组成员集合、当前选择集合、队形成员集合是不同对象。

## 8. 扁平化主题与遮挡规则

采用统一深色面板、细分隔、少量阵营/状态强调色；减少每块信息的厚边框，保留按钮可点击感。冷却遮罩、自动施法边框、禁用原因、键位角标、物品数量必须能同时辨认；不要在图标中心堆叠所有文本。

统一布局结构建议：HudRoot → TopStatus、HeroRoster、GlobalProduction、BottomDock、NotificationRegion、TooltipLayer、ModalLayer、独立 DebugOverlay。BottomDock 内由容器分配小地图、详情、扩展与命令区，控制组占专用行。覆盖层顺序需明确，但 z-index 不能用于掩盖普通面板互相挤压。

Tooltip 限制在视口内，优先避开当前目标与命令按钮，空间不足换侧；长内容允许固定详情弹层。通知区限制数量和寿命，支持历史展开。世界输入只被实际可交互 UI 区域阻挡，透明 HUD 根不得吞掉整个世界鼠标输入。

面板模式：空选只保留必要操作；普通单位展示核心属性；英雄加入经验/物品；建筑加入生产；多选改为类型摘要。高频生命、冷却、进度局部刷新，布局树只在选择类型/结构变化时切换。

## 9. UI 代码模块与分波次落地

View 只负责控件，Presenter/ViewModel 负责订阅、格式化和局部更新，Gameplay 提供只读快照与命令结果。模块包括 HudLayout、SelectionDetails、CommandPanel、HeroRoster、InventoryView、ProductionOverview、ControlGroupBar、Minimap、Notifications、Tooltip、Settings/InputBindings。共享 Theme/控件，不创建万能 UIManager。

| 阶段 | 工作 | 验收 |
|---|---|---|
| U0 | 现状截图、矩形记录、模拟数据预览场景 | 覆盖长名称、16+ 多选、多个队列、英雄满背包等，不依赖完整对战才能预览 |
| U1 | 统一底栏容器、响应式模板、输入阻挡与开发叠层 | 无普通面板重叠/裁切，低分辨率和高缩放可操作 |
| U2 | 生产/研究总览、稳定任务身份与定位 | 当前/等待语义正确，同类型多建筑不误定位，取消/退款走正常规则 |
| U3 | 英雄条、英雄详情、背包布局、控制组栏 | 选择不意外改变、死亡/复活稳定、成员移除无失效引用 |
| U4 | 热键预设、重绑、输入上下文、主题统一 | 镜头与命令不冲突，文本输入不触发技能，重启保留配置 |

状态覆盖：空选、单选、16/100 单位混选、英雄满级/技能点/死亡/复活、普通单位背包、建筑施工/训练/研究/升级、多个同类建筑、队列暂停/取消、敌方与迷雾、长中英文名称、Tooltip 四角。

画面覆盖：1280×720、1366×768、1920×1080、2560×1440、2560×1080，以及适用的 UI 100/125/150%。截图验证与矩形相交断言同时进行；预期的 Tooltip/模态覆盖列入白名单，普通面板不能互相遮挡。隐藏面板不得继续阻挡世界操作。

保持已有命令卡动态刷新节奏，稳定状态不重复生成按钮/图标/布局。性能比较同场景同单位数的 UI 更新与整帧 P95，不将 headless 数据换算成渲染 FPS。

本轮只记录方案；没有改现有 HUD 场景、游戏逻辑、按键绑定或视觉资源。与当前并发 Gameplay 重构分别推进，实施前按最新路径复核引用。
